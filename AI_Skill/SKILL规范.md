# SKILL 制作规范（AI_Skill 质量门禁）

> 本规范是 `AI_Skill/skills/` 下所有技能的制作、评审、修订标准。新增技能必须逐条对照；修订技能不得降低达标项。

## 1. 文件与命名规范

1. **目录名**：小写 kebab-case 英文（如 `cache-algorithms-advanced`），与 frontmatter `name` 一致；同一主题多个技能时以 `-` 后缀区分。
2. **文件名**：一律 `SKILL.md`（单文件技能）；参考资料超 300 行时可拆 `reference.md` 同目录存放，正文须回链。
3. **frontmatter**：仅允许 `name` / `description` 两个字段；`description` 一句话同时说明"做什么+何时用"（含中英文关键词），≤200 字符。禁止把项目内部口号、未证实结论写入 description。
4. **正文语言**：中文（与项目一致）；论文标题、命令、代码、专有名词保持原文。

## 2. 结构规范（必须按序包含以下 8 节）

| 节 | 名称 | 内容要求 |
| -- | ---- | -------- |
| §1 | 概述与适用场景 | 本技能覆盖范围、何时调用、不覆盖什么（防误用） |
| §2 | 核心要点 | 5-12 条决策级要点，每条可独立成立；术语与项目 [概念定义汇总](../docs/00-项目总览/概念定义汇总.md) 一致 |
| §3 | 权威速查 | 表格/清单形式的参数、公式、默认值、命令；公式必须给出处（或标"推导自 XXX"） |
| §4 | 项目文档映射 | 表格：本技能知识点 → `docs/` 具体文档相对路径（必须真实存在） |
| §5 | 常见任务工作流 | agent 可执行的步骤化流程（含验证命令） |
| §6 | 国际前沿对齐 | 最近 24 个月关键进展 + 出处；标注"截至 YYYY-MM" |
| §7 | 验证命令 | 可执行命令（与 Testing 用例 ID 对应），标注预期结果 |
| §8 | 权威参考 | 分级列出：A 学术论文（会议/年份）、B 官方文档（URL）、C 工程资料；不编造文献 |

## 3. 内容质量门禁

1. **出处**：事实性论断（性能数字、版本号、算法结论）必须有 A/B 级出处；经验性判断标 C 级并声明假设。
2. **链接**：所有相对路径链接必须真实存在；`docs/` 链接用相对路径（如 `../../docs/01-理论基础/...`），提交前用 `python Testing/self_verify.py links --path AI_Skill` 验证。
3. **代码**：skill 内代码块必须语言标注真实、可在目标平台运行；Windows 相关示例遵循 [AGENTS.md](../AGENTS.md) §4.2.4 平台守卫禁令。
4. **前沿时效**：版本号、会议年份每季度核验；过期信息标 `~~删除线~~` 并写新值，不留无标注的过期内容。
5. **一致性**：与 `docs/` 正文冲突时，以权威出处仲裁并同步修订建议（写入 [STATUS.md](../docs/00-项目总览/STATUS.md) 变更记录），禁止 skill 与正文长期矛盾。
6. **反元文档**：skill 不得写成"完成报告/总结陈词"，只写可复用的知识与流程（[AGENTS.md](../AGENTS.md) §4.2.1）。

## 4. 评审流程

```text
新建/修订 → 按 §2 结构自检 → 按 §3 门禁逐条核对
  → python Testing/self_verify.py all（无回归）
  → 更新 AI_Skill/README.md 清单行（状态/前沿日期）
  → 季度评审时统一核对"国际前沿对齐"节
```

不合格常见项（历史经验）：description 写成人话口号、§4 链接指向不存在的文档、版本号无出处、代码块语言标注虚假。

## 5. 版本与变更

- skill 变更记录集中维护在本文件与 [AI_Skill/README.md](README.md) 的"前沿更新时间"，不逐 skill 建变更日志（反元文档）。
- 重大结构调整（增删节）需同步修订 [SKILL模板.md](SKILL模板.md) 与 [示例模型.md](示例模型.md)。
