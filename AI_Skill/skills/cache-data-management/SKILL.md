# 缓存数据管理（分片数学 · 操作复杂度 · 序列化布局）

> 覆盖缓存数据的三个纵深维度：分多少片/迁移多少（数学）、每类操作花多少（复杂度）、数据怎么存最省（布局）。批次 E 交付分片数学；操作复杂度与序列化随批次 F 充实。

## 1. 概述与适用场景

- **覆盖**：分片数量统计性质、再平衡成本模型、热点倾斜度刻画（批次 E）；六大数据类型操作算法与复杂度、序列化编码权衡（批次 F）。
- **适用**：分区/扩缩容设计的数学论证；慢操作根因分析（操作×bigkey 放大）；容量评审的公式输入。
- **不适用**：放置算法选择（→ distributed-cache-algorithms）；Pod/节点层伸缩（→ elastic-selfhealing）。

## 2. 核心要点

1. 分片数 n 越大，随机放置的相对热点越温和：最忙分片期望负载 ≈ (ln n / ln ln n)·均值（球箱模型，Gonnet 1981），n=100 时约 4.2 倍。
2. 虚拟节点 v 个使物理节点负载方差缩减为单点方差的 1/v（Karger STOC'97 分析）；工程惯例 v≥10·ln n。
3. Redis Cluster 16384 槽 = 心跳 bitmap 大小（S/8 字节）× 迁移粒度 × tag 冲突率的权衡解。
4. 再平衡迁移量：一致性哈希 ≈1/(n+1)；迁移时间 = 源 dump + 数据/带宽 + 目标加载；迁移期间源与目标双份内存。
5. 热点判定用可测指标：槽负载倾斜度 P99/P50 QPS >3 持续 15min；数据倾斜度 max/median 内存 >2。
6. 跨槽操作无快照一致性：聚合查询结果是多分区瞬时值拼接（04.44.08 论证）。
7. （批次 F 预留）操作复杂度以官方大 O 表+实现差异为准，bigkey 下操作放大 = 复杂度 × 元素数。

## 3. 权威速查

| 项 | 值 | 级别 |

## 5. 常见任务工作流

### 任务 A：分区设计评审

1. 数据量 D、迁移窗口 T、迁移带宽 B → 槽数下界 S ≥ D/(B·T)（01.03.05 §2.3）。
2. 峰值 QPS 与分片数 n 的吞吐匹配（单分片上限按 07.05.04 基线打折）。
3. 热点预测：key 独立性检验（访问簇建模），不独立时泊松假设作废。
4. 输出：S/n/迁移成本表 + 倾斜度监控指标定义。

### 任务 B：再平衡预案

按 01.03.05 §3 成本模型估算 T_migrate，窗口选择低峰，带宽隔离；演练用 TC-CLUS-008。

## 6. 国际前沿对齐（截至 2026-11）

- 分片数学为稳定经典（球箱/Karger 无变动）；前沿在自动化再平衡（Operator 驱动，见 cloud-native-cache）。
