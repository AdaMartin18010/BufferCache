# 全栈分析（硬件到算法的纵深方法论）

> 覆盖 05-全栈分析主题 41 篇文档的方法体系：请求在缓存系统中穿过的每一层怎么度量、怎么算账、怎么定位瓶颈。

## 1. 概述与适用场景

- **覆盖**：硬件层（CPU/NUMA/SSD/网卡 DMA）、网络层（TCP/epoll/零拷贝/io_uring）、控制流（事件循环/状态机/BIO）、数据流（请求-响应/持久化/复制/延迟分解）、算法层（近似 LRU/LFU/哈希/压缩实现）、动态特征（延迟分布/Little 定律/故障传播/抖动/边界估算）、瓶颈分析。
- **适用**：性能问题的分层定位（从哪个层开始查）；延迟/吞吐账的测算；容量与瓶颈评估。
- **不适用**：具体算法选型（→ cache-algorithms-fundamentals / cache-algorithms-advanced）；运维操作（→ cache-operations-testing）。

## 2. 核心要点

1. 分层定位顺序：**自上而下验证假设、自下而上排除物理层**——延迟异常先看数据流账（05.04.04），账对不上再往下层挖（05.02/05.01）。
2. 延迟分解基本式：$T_{total} = T_{网络} + T_{排队} + T_{处理} + T_{持久化}$，每层有对应文档的实测方法（05.04.04 延迟分解）。
3. Redis 关键路径：aeEventLoop 事件循环（05.03.01/02）→ 命令查找执行 → 回复缓冲；多 IO 线程只承担读写卸载（05.03.03）。
4. 算法实现层是"理论算法的工程折中"：近似 LRU（采样）、对数计数 LFU（05.05.01/02）——分析性能时区分理论复杂度与实现常数。
5. 动态特征三件套：Little 定律（L=λW，05.06.02）、延迟分布建模（05.06.01）、故障传播图（05.06.03）——容量与稳定性的统一度量。
6. 边界估算（05.06.07）：M/M/1 反解 μ=λ+1/W + USL 拐点外推 + 饱和度先行指标——"当前配置边界在哪"的量化方法。
7. 瓶颈分析的排除法：CPU/内存带宽/网络/磁盘四类边界取最小（05.07.01），perf/USE 方法定位。

## 5. 常见任务工作流

### 任务 A：延迟异常分层定位

1. 算数据流账（05.04.04）：逐段分解并对比基线，定位异常段。
2. 段落在网络层？→ 05.02 方法（TCPCopy/延迟分解）；在处理层？→ SLOWLOG/LATENCY DOCTOR（07.07.03）；在持久化？→ fork/AOF 指标（03.02.06）。
3. 输出：分层账表 + 异常段归因 + 修复建议。

### 任务 B：容量与边界评估

1. Little 定律验并发模型（05.06.02）；2. 边界反解当前利用率（05.06.07 §2.1）；3. 瓶颈四资源取最小（05.07.01）；4. 输出：边界余量 + 扩容触发线（联动 07.09 弹性）。

## 6. 国际前沿对齐（截至 2026-11）

- io_uring 持续增强（FUSE over io_uring 6.17、bpf-ops），零拷贝路径新组合（05.02.03/04）。
- 性能分析方法论：eBPF 全栈追踪（Pixie/Cilium）替代部分 perf 场景；OTel GenAI 语义约定覆盖 LLM 缓存链路（04.03.18）。
- USL/排队论为稳定经典；前沿在"AI 辅助拐点检测"（C 级趋势）。
