## 一、矩阵清单与维度模型

| 矩阵 | 维度模型 | 规模 |
| ---- | ---- | ---- |
| MX-A 算法正确性 | 算法(10) × 验证手段(5) | 50 格 |
| MX-B 部署×故障 | 形态(4) × 故障域(6) | 24 格 |
| MX-C 性能负载 | 读写比(4) × 对象大小(4) × 工具(2) | 32 格（分两表） |
| MX-D 客户端×操作族 | 语言(3) × 操作族(8) | 24 格 |
| MX-E 安全 | 域(6) × 手段(3) | 18 格 |
| MX-F LLM KV Cache | 机制(4) × 手段(3) | 12 格 |
| MX-G 文档知识覆盖 | 主题域(8) × 质量项(5) | 40 格 |

取值定义与权威源锚见 `维度定义/*.tsv`（code/name/source 三列）。

## 二、用例编码与路径规则

```text
用例 ID:  TC-MX<A-G>-<DIM1>-<DIM2>[-<NN>]     （DIM 码见各维度 TSV；同格多用例 -NN 递增）
文件路径: cases/<mx小写>/<dim1小写>/<dim2小写>/TC-....md   （首两层走目录，同环境聚合复用）
机读登记: matrix-registry.tsv 一行（case_id/mx/dim1/dim2/[dim3]/status/note）
status 生命周期: seed(种子人工精修) → gen(生成器铺底) → done(执行闭环)
```

ID 空间与 cases/00-05 现有 TC-XXX-NNN 隔离；防重对账由 `tools/matrix_gen.py --check` 执行（已入 self_verify 矩阵组）。

## 三、适用矩阵四态（不空判据）

每格必须处于且仅处于四态之一，写入 `适用矩阵.md`：

- **●** 适用：有（或将建）对应用例；
- **○-架构**：该形态/组合架构上不支持（写明理由，如 Sentinel 形态无槽概念）；
- **○-环境**：适用但环境缺席（如 GPU 实测、memtier 镜像），SKIP 语义，环境恢复后转 ●；
- **○-无意义**：组合无验证价值（写明理由）。

"待补"不是终态——M2 种子批与 M3 扩展批负责把全部格子落定到上述四态之一（不漏判据）。

## 四、与现有体系的关系（不重判据）

- 现有 35 用例（cases/00-05）在 M2 逐格映射归位：被矩阵格覆盖的，格内"关联"行指向原用例文件而非重写；确属重复的，在适用矩阵注记合并裁定（候选：DOC-005×BENCH-001 部分重叠、INT-001×self_verify 同对象）。
- 矩阵用例多数为 L2/L3 剧本型，**不全部入 self_verify**；入 self_verify 的仅 `matrix_gen.py --check` 一致对账一项（门禁）。
- 执行调度进 测试与验证执行计划 §7 任务卡（M4）；覆盖看板进 用例全景统计"矩阵覆盖"节（M5）。
