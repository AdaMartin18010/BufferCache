## 预期结果（2026-11-17 基线，60 会话/64 块池）

| 策略 | 复用率 | 说明 |
| ---- | ------ | ---- |
| LRU | 79.9% | 基线 |
| FIFO(S3) S=10% | **0%** | S 段 6 块 < 共享前缀 13 块 → 前缀被挤出，塌缩 |
| FIFO(S3) S=30% | 79.9% | S 段 19 块 > 前缀 → 恢复 |
| SIEVE | 79.9% | visited 位保护前缀，对准入容量不敏感 |

**机制结论**：前缀共享型 LLM 负载下，FIFO 系（S3）对小准入段容量敏感——S 段须 ≥ 最长共享前缀块数；LRU/SIEVE 无此约束。该发现已回写 04.03.15 相关讨论（驱逐策略选型需计入前缀长度）。

## 失败纠正与修正指引

1. S3 复用率非 0 但 SIEVE 异常低：检查 SIEVE 驱逐指针逻辑（全访问过的淘汰分支）。
2. 三策略全 0：负载生成失效（会话数 ≤ 块池容量时无驱逐压力属正常，调 --sessions）。
3. 修正：与 libCacheSim PrefixSim 的对比口径差异（本实验为教学级简化，结论以机制定性为主）。
