# 测试与验证执行计划（总纲）

> 本计划定义 BufferCache 项目的**分层验证体系与持续迭代执行机制**：谁执行（CI / hermes 本地代理 / 人）、何时执行、产出去哪、如何验收汇总。规划由 AI 协作者维护；**执行由对应角色按计划自主进行，执行结果回填本文件与用例文件**。
>
> 定位：[Testing/README.md](README.md) 是"有什么用例"，本文是"怎么持续跑、怎么算验收"。

## 1. 四层验证模型

```text
L1 门禁层（自动化）     self_verify 24 检查项 —— 每次提交/CI，<6min
L2 环境层（半自动）     Docker 演练用例 TC-CLUS-001~009/TC-OPS-005 —— hermes 按轮换表，周/月
L2.5 动态验证层（脚本） 自愈模拟/稳态巡检/边界复算/技能自测 —— hermes 每次会话可选跑，<3min
L3 集成层（剧本化）     场景串联剧本（部署→监控→注入→恢复→验收）—— hermes 月度，30-60min
L4 验收层（汇总）       月度验收报告（结果汇总+趋势+缺口）—— hermes 生成，人审
```

层间关系：L1 全过是 L2 的前提；L2 月度覆盖 ≥ 计划值的 80% 是 L4 验收通过的条件；L3 每季度 ≥1 次完整剧本；L4 产出反哺计划修订（新风险→新用例→L2 轮换表）。

## 3. hermes 本地执行手册（每次会话）

```text
开工自检（3min）：
  0. 容器运行时探测（容器适配规范 §1：docker→podman→k8s→无），结果记入会话记录
  1. python Testing/self_verify.py all        # L1 全量，确认基线绿
     └─ 运行时可用时自动含 lab/bench 实测；不可用 SKIP 不阻断
  2. 查 [用例全景统计](用例全景统计.md) §5 待执行队列 + 本计划 §6 轮换表 → 判定到期任务
  2b. 动态验证（可选，<3min）：
      python scripts/selfheal_sim.py        # 自愈预算回归
      python scripts/steady_state_check.py  # 稳态漂移（自动探测 exporter，缺则模拟）
      python scripts/boundary_recheck.py --from-bench  # 有余量时跑，无则 SKIP
      python scripts/skill_selftest.py      # 技能动态自测（20 技能）
  2c. 深读队列：每会话取 [deep_read_queue](deep_read_queue.md) 1-2 卡执行

到期执行（按用例文件的步骤）：
  3. 按 [容器运行时适配规范](容器运行时适配规范.md) §2 把命令适配到当次运行时
  4. 逐条执行，每步记录：时间/命令/输出关键值/是否符合预期
  5. 异常处理：环境缺失→跳过并记 SKIP；结果偏离预期→按用例"修正指引"处理
     （能修的修，不能修的登记 STATUS.md 待办，不伪造通过）

收尾（5min）：
  6. 回填：用例文件"执行记录"节 + 演练数据回填对应 docs 文档（07.04.03/07.05.04/07.09.04 等）
     + 用例全景统计 §5/§6 状态更新
  7. 若当月 L2 用例全部完成 → 生成 §5 验收报告草稿
  8. git 提交（执行记录 + 数据回填），提交信息标注"hermes 例行执行"
```

新增用例/检查项的开发约定见 [测试框架规范](测试框架规范.md)。

## 4. L3 集成剧本（场景串联）

**剧本 S1 综合韧性演练**（季度，60min）：

```text
前置：cluster + sentinel + monitoring + toxiproxy 全栈在跑，基线数据已造
1. 稳态确认（5min）：命中率/延迟基线达标（07.09.03 §2.1 稳态假设）
2. 注入 A（10min）：toxiproxy +400ms 延迟 → 观测客户端超时率与熔断（07.09.02 §5 L4）
3. 注入 B（15min）：pause 主库 → Sentinel 转移计时（TC-CLUS-003）→ 恢复归队
4. 注入 C（15min）：kill cluster 主节点 → 转移+槽覆盖验证（TC-CLUS-004）
5. 验证（10min）：监控栈告警全触发（TC-OPS-005-C）；对账抽检 100 key（04.44.11）
6. 验收（5min）：稳态恢复判定 + 全链路计时汇总 → L4 报告输入
中止条件：命中率 >5% 持续 60s（Chaos Mesh 同款护栏，07.09.03 §2.2）
```

剧本扩展规则：新故障域（如时钟漂移、磁盘写满）经季度评审批准后写成 S2/S3，结构与 S1 同构。

**剧本 S2 环境退化剧本**（半年，45min）：

```text
1. 稳态确认（5min）：同 S1
2. 注入 A（10min）：容器磁盘写满模拟（docker exec 写大文件占满 /data 卷）
   → 观测：AOF 写失败告警时延；noeviction 下写命令错误率（03.02.06 §3 表）
3. 注入 B（10min）：时钟漂移演示（容器内 date 调整 + Sentinel 选举观测；
   TLS 证书校验、expire 精度影响见 07.09.03 §4 时钟域）
4. 注入 C（10min）：slowlog 注入（DEBUG SLEEP 0.05 循环）→ 客户端超时熔断（03.06.07 矩阵验证）
5. 验收（10min）：恢复路径验证（磁盘清理/时钟回正后自动恢复情况）→ 报告
中止条件：磁盘 >90% 持续 60s（防真占满宿主）
```

**剧本 S3 跨分区剧本**（季度，与 S1 隔月执行，50min）：

```text
1. 稳态确认（5min）
2. 注入（15min）：toxiproxy 切断主↔从通道（timeout toxic 100%）→
   min-replicas-to-write 拒写生效观测（03.06.06 背压与 07.09.02 §3 脑裂防护验证）
3. 恢复（10min）：通道恢复 → 复制追赶（部分重同步 vs 全量判定，backlog 容量验证 07.05.02）
4. 对账（15min）：分区窗口写操作的主从一致性抽检（04.44.11 工具，100 key）
5. 验收（5min）：双端一致率 ≥99% → 报告
```

## 5. L4 验收汇总（月度报告模板）

hermes 每月末生成 `Testing/output/acceptance_YYYY-MM.md`（gitignore，摘要入 STATUS 变更记录）：

```markdown
# 缓存体系验收报告 2026-12
## 执行覆盖：L2 计划 5 项 / 完成 4 项（TC-CLUS-008 环境缺失 SKIP）
## 结果摘要：
- L1 门禁：本月 132 次运行全绿（CI 130 + 本地 2）
- 故障转移 RTO：Sentinel 10.2s（预算 15s ✓）；Cluster 38s（预算 40s ✓）
- 备份恢复 RPO：0 keys 丢失（✓）
- 混沌注入：延迟注入可逆（✓）
- 基准回归：4 场景对基线偏差 +2.1%~+6.8%（阈值 15%，✓）
## 漂移与纠正：本月事实巡检 0 漂移；发现 X 问题已修（链接）
## 缺口与计划：下月补 TC-CLUS-008；Q1 首次剧本 S1
```

验收通过与门禁等效：报告无 🔴 项即本月验收通过；连续两月覆盖率 <80% → 升级到人审。
