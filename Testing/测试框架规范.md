# 测试框架规范（self_verify + 脚本 + 用例的开发约定）

> 本规范定义 BufferCache 测试体系的**开发层约定**：如何新增检查项、脚本编写规范、用例文件模板、命名与分组规则、统计口径。规划与规范由我（AI 协作者）维护；hermes 按规范执行与回登数据。与 [测试与验证执行计划](测试与验证执行计划.md)（执行分工）互补。

## 1. self_verify 检查项注册规范

```python
# 1) 实现检查函数：返回 "状态\n详情"（状态 ∈ PASS/FAIL/SKIP）
def check_xxx() -> str:
    """TC-XXX-NNN: 一句话目的"""
    ...

# 2) 注册（CHECKS 列表，按组内 ID 序插入）：
Check("TC-XXX-NNN", "短标题", "<组名>",
      "cases/<组目录>/TC-XXX-NNN-<名称>.md", check_xxx, slow=<bool>),

# 3) GROUPS 映射：all 列表必须包含新组；独立子命令同步添加
```

**铁律**：

- 慢检查（>10s）标 `slow=True`；同组多检查项共享一次运行的，用模块级缓存字典（参照 `_OPS_CACHE`/`_GOV_CACHE` 模式），禁止重复执行。
- 环境依赖一律 **SKIP 而非 FAIL**（缺 Java/Redis/Docker/mkdocs 都 SKIP），并在详情说明启用条件。
- 外部命令探测用 `which()`；Windows 路径问题用绝对路径兜底。
- 检查器自身变更必须过 TC-INT-001 全量回归。

## 2. 脚本规范（scripts/ 下测试工具）

| 项 | 约定 |
| -- | ---- |
| 入口 | `if __name__ == "__main__": sys.exit(main())`；退出码 0 成功 / 1 失败 / 2 SKIP |
| 依赖 | 运行时依赖只准标准库 + requirements.txt 已锁定项；可选依赖 try-import 后降级 SKIP |
| 参数 | argparse；连接类参数（--host/--port/--password）齐全；随机性必须 --seed 可复现 |
| 输出 | 人类可读表格 + `--json` 结构化输出（基准/对账类必须）；状态行用 `PASS/FAIL/SKIP` 开头便于 grep |
| 平台守卫 | 涉及 OS 差异的示例遵守 AGENTS.md §4.2.4（sys.platform 检查）；脚本本身跨平台（不硬编码盘符） |
| 产物 | 输出只写 `Testing/output/`（gitignore）或 stdout；**禁止**写 reports/ 以外的新报告目录 |
| 语言标注 | 脚本引用的文档代码块保持真实语言（TC-DOC-002 扫描范围） |

## 3. 用例文件模板（cases/ 下，含运行时标注）

```markdown
# TC-<域>-<NNN> <名称>

- **用例ID**：TC-XXX-NNN | **优先级**：P0-P2 | **自动化**：self_verify 已覆盖（`<组>`）·部分覆盖·人工
- **运行时**：ANY｜DOCKER+PODMAN｜DOCKER（暂）｜K8S（扩展）   ← L2/L3 必填，L1 省略
- **目的**：一句话（验证什么能力/补什么盲区）
- **关联**：脚本/文档/用例的相对链接（层级：cases/<组>/ 下文件到根用 ../../../）

## 前置条件
## 步骤（命令必须是当次运行时适配后的形态——Docker 为基准形态，差异见容器适配规范 §2）
## 预期结果（含实测基线的日期与数值）
## 失败纠正与修正指引（纠正=修本次；修正=防复发）
## 执行记录（hermes 回填：日期/环境/结果/耗时）
```

## 4. 命名与分组规则

| 域 | 范围 | 说明 |
| -- | ---- | ---- |
| TC-DOC | 文档质量 | 代码块/标注/链接/导航/统计/站点/一致性巡检 |
| TC-FORM | 形式化 | TLA+ 及后续证明工具 |
| TC-BENCH | 可执行基准/模拟 | trace/一致性/容量/基准/治理/KV 驱逐 |
| TC-OPS | 运维静态/半自动 | 配置/规则/安全基线/弹性配置/监控栈 |
| TC-SEC | 安全 | 仓库体检 |
| TC-CLUS | 集群/灾备/混沌演练 | 人工为主，hermes 按轮换表执行 |
| TC-INT | 集成 | 全量回归/CI 与版本监控 |

- ID 组内连续不重号；跨组不复用。
- 新域开组需同步：README 结构图 + 执行计划 §2 矩阵 + GROUPS。

## 5. 统计口径（L4 验收与 README 数据的唯一标准）

| 指标 | 口径 |
| ---- | ---- |
| 用例总数 | cases/ 下 .md 文件数（不含模板/归档） |
| 自动化率 | self_verify 已覆盖项 / 总数（部分覆盖按 0.5 计） |
| L1/L2/L3 分布 | 按执行计划 §2 矩阵的分层列 |
| 门禁检查项 | self_verify CHECKS 长度（当前 24：20 项注册含合并组） |
| 通过率 | PASS /（PASS+FAIL）（SKIP 不计入，单独报告） |
| 覆盖率（L2） | 当月实际执行用例 / 轮换表计划数；环境缺席记"缺席"非"未完成" |
| 漂移纠正数 | 事实巡检与人工发现的正文事实修正累计 |

统计快照每月随验收报告刷新；README 的"29 用例/20 检查项"类数字以本口径为准更新。

## 6. 测试数据与 fixture 规范

- `Testing/fixtures/` 下数据文件（trace CSV、compose、prometheus 配置）**入库**（小且稳定）；运行产物（RDB/AOF/基线 JSON/报告）**不入库**（gitignore）。
- 造数脚本（如 redis-lab 的 drill key）写在用例步骤里，不留隐藏状态；演练后环境可 `down -v` 完全重建。
- 密码等凭据只允许 `lab-password` 级测试值（TC-SEC-001 会扫描硬编码）。
