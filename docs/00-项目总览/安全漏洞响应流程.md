# 安全漏洞响应流程

> TC-SEC-001 是预防基线；本流程定义**项目收到缓存相关漏洞情报后的响应**。触发源：[版本监控](../../scripts/version_monitor.py)（新 CVE 提示）、人工上报、巡检发现。

## 1. 响应 SLA（按 CVSS 分级）

| 级别 | 判定 | 响应时限 | 动作 |
| ---- | ---- | -------- | ---- |
| P0（严重，CVSS ≥9 或野外利用） | 影响项目在用版本/演练环境 | 24h 内评估，72h 内处置 | 隔离→修复版本→全量回归→发布说明 |
| P1（高，7-8.9） | 影响场景可触发 | 7 天内评估与处置计划 | 配置缓解或版本升级 |
| P2（中低，<7） | 条件触发 | 随下个维护窗口 | 登记跟踪 |

## 2. 流程五段

```text
接收（版本监控/上报）→ 评估（受影响版本×暴露面×缓解可行性）
  → 处置（升级/配置缓解/接受风险——必须书面理由）
  → 验证（TC-SEC-001 + 全量门禁 + 环境针对性复测）
  → 归档（STATUS 变更记录 + 事实断言清单 + 本文件附录登记表）
```

## 3. 处置原则

1. **演练环境同责**：redis-lab 等 fixtures 用的版本同样在评估范围（容器镜像 tag 登记于 Testing/fixtures/）。
2. **缓解优先**：无法立即升级时，配置缓解（rename-command/绑定/ACL）先行，缓解措施过 TC-OPS-003 静态检查。
3. **不静默接受**：接受风险必须登记理由（不可升级的业务理由+补偿控制），随季度评审复审。
4. **上游协同**：项目文档引用的版本事实（03.05）随 CVE 更新同步修订，保持"事实断言清单"不失真。
