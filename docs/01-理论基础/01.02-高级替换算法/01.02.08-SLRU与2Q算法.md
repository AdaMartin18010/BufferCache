## 1. SLRU（分段LRU）

### 1.1 设计动机

朴素 LRU 在两种负载下失效：

1. **扫描型负载**：一次性顺序遍历大量数据（全表扫描、备份、日志回放），扫描对象短暂进入缓存后立即淘汰——但过程中驱逐了真正的热数据（缓存污染）
2. **分层局部性负载**：数据存在"稳定热点"与"突发访问"两个群体，单一链表无法区分其重要性

SLRU（Segmented LRU，Karedla et al., IEEE Computer 1994）将缓存划分为**多个分段（segment）**，对象在分段间晋升，仅在最低段内驱逐——为"被再次访问过"的对象提供保护。

### 1.2 算法结构

将缓存容量划分为 $m$ 个段（常用两段）：

```
[  probation段（试用） | protected段（保护） ]
       容量 80%              容量 20%
  ← 新对象从这里进入      二次命中的对象晋升到这里
  ← 驱逐只发生在这里      满了则从段尾降级回试用段
```

- **试用段（Probation）**：新对象进入；驱逐候选的来源
- **保护段（Protected）**：至少被访问过两次的对象；驱逐压力时降级

### 1.3 晋升与驱逐规则

1. **miss 且键不在缓存**：插入试用段 MRU 端
2. **hit 且对象在试用段**：晋升至保护段 MRU 端
3. **hit 且对象在保护段**：移至保护段 MRU 端
4. **驱逐**：试用段 LRU 端；若保护段溢出，其 LRU 端降级至试用段 MRU 端

**形式化**：设段容量为 $c_1$（试用）、$c_2$（保护），$c_1 + c_2 = k$。对象 $x$ 的状态：

$$state(x) \in \{probation, protected\}$$

状态转移由命中历史驱动，转移图构成两层的"使用证据"漏斗。

### 1.4 性能特征

- **扫描抵抗**：一次性扫描对象只进入试用段，驱逐发生在试用段内，保护段热数据不受影响
- **近似实现 LFUDA/分层 LRU**：多层分段（如 3-4 段）可逼近频率语义——段编号即"命中次数的饱和计数"
- **参数**：段比例（如 80/20）对命中率影响平缓；段数增加粒度变细但管理成本上升
- **竞争性质**：SLRU 仍是 $k$-competitive 类算法的变体，但扫描场景的有效竞争比远优于纯 LRU

## 2. 2Q算法

### 2.1 设计动机

Johnson & Shasha（VLDB 1994）针对数据库缓冲池的扫描问题提出 2Q，与 SLRU 思想同源但结构不同：用一个**短 FIFO 队列**充当"准入过滤器"，只有经受住时间考验的对象才进入主 LRU。

### 2.2 双队列结构

```
[ A1in（FIFO准入队列） | Am（主LRU队列） | A1out（幽灵队列） ]
     容量 25%              容量 75%
  新对象先进入这里      二次命中的长期驻留
  溢出直接淘汰          A1out 记录被淘汰对象的历史
```

- **A1in**：FIFO 队列，新对象短暂停留（"第一个 Q"）
- **Am**：主 LRU（"第二个 Q"）
- **A1out**：幽灵队列（已在 A1in 被淘汰的键的历史记录，不占数据空间）

### 2.3 准入与晋升规则

1. **miss，键不在任何队列**：入 A1in 头部
2. **miss，键在 A1out**：说明对象"复活"（曾被快速淘汰后又被需要）→ 直接入 Am 头部
3. **A1in 溢出**：尾部键移入 A1out（幽灵化）
4. **hit 且键在 A1in**：不动（FIFO 语义，不做 LRU 提升）
5. **hit 且键在 Am**：移至 Am 头部（LRU 语义）
6. **Am 溢出**：尾部直接淘汰

**关键参数**：KinRatio（A1in 容量占比，论文建议 0.25）、KoutRatio（A1out 容量，论文建议为 Am 的 0.5 倍）。

### 2.4 与LRU-K的关系

2Q 可视为 LRU-2 的常数时间近似：LRU-2 维护精确的"倒数第二次访问时间"，排序开销高；2Q 用"是否经历过一次淘汰（A1out 命中）"作为"访问间隔较长"的粗糙代理，换取 O(1) 操作。**思想谱系**：LRU-K → 2Q（准入过滤）→ ARC（幽灵队列自适应化）→ TinyLFU（频率准入）。

## 3. 两种算法的对比

| 维度 | SLRU | 2Q |
| ---- | ---- | ---- |
| 结构 | 两段 LRU | FIFO 准入 + LRU 主体 |
| 保护机制 | 二次命中晋升保护段 | FIFO 停留期过滤扫描 |
| 幽灵/历史 | 无 | A1out 记录淘汰历史 |
| 扫描抵抗 | 强（保护段隔离） | 强（A1in 吸收扫描） |
| 实现复杂度 | 低（两段链表） | 低（FIFO + LRU） |
| 参数 | 段比例 | Kin/Kout 比例 |
| 代表应用 | 中间件缓存、CDN 分层 | PostgreSQL 缓冲池（Clock-sweep 近似）、MySQL 变体 |

**统一视角**：SLRU 与 2Q 都是"**两阶段证据漏斗**"——对象必须提供两次使用证据才能进入长期驻留区。差异在于证据的判定：SLRU 用"命中"，2Q 用"经受住 FIFO 停留期"。

## 4. 应用场景

- **PostgreSQL**：缓冲区管理使用 Clock-sweep 变体（8.0 前的 LRU 和中期的 ARC 曾被讨论；现代实现 clock-sweep 近似 2Q 思想： Usage Count 作为证据累积）
- **Apache / CDN 分层缓存**：SLRU 结构实现多级保护
- **CPU 与磁盘预取缓冲**：两段式冷热分离
- **与 TinyLFU 组合**：Caffeine 类系统用 TinyLFU 做准入（频率证据）+ SLRU 式窗口缓存（时间证据），融合两条谱系

## 5. 实现要点

```python
class SLRU:
    def __init__(self, capacity: int, protected_ratio: float = 0.2):
        self.probation = OrderedDict()   # 试用段
        self.protected_cap = int(capacity * protected_ratio)
        self.probation_cap = capacity - self.protected_cap
        self.protected = OrderedDict()   # 保护段

    def get(self, key):
        if key in self.protected:
            self.protected.move_to_end(key)
            return self.protected[key]
        if key in self.probation:
            # 晋升到保护段
            val = self.probation.pop(key)
            self.protected[key] = val
            if len(self.protected) > self.protected_cap:
                # 降级最老的保护对象
                k, v = self.protected.popitem(last=False)
                self.probation[k] = v
                if len(self.probation) > self.probation_cap:
                    self.probation.popitem(last=False)  # 驱逐
            return val
        return None

    def put(self, key, value):
        if key in self.protected:
            self.protected.move_to_end(key)
            self.protected[key] = value
        elif key in self.probation:
            self.get(key)  # 触发晋升
        else:
            self.probation[key] = value
            if len(self.probation) > self.probation_cap:
                self.probation.popitem(last=False)  # 驱逐
```
