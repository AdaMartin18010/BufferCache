## 1. CLOCK-Pro：懒惰晋升的时钟算法

### 1.1 设计动机

CLOCK（时钟扫描）以 O(1) 开销模拟 LRU，但存在两个缺陷：

1. **无访问频率语义**：单次访问即可让页长期驻留（second-chance 只检查"是否被用过"）
2. **扫描敏感**：顺序扫描会获得大量 second chance

LRU-K/LIRS 引入间隔语义（inter-reference recency），但 LIRS 的实现开销（维护 IRR 与 LIR/HIR 集合）在实用中偏高。CLOCK-Pro（Jiang & Zhang, USENIX ATC 2005）的目标是：**以 CLOCK 的实现复杂度逼近 LIRS 的效果**。

### 1.2 与CLOCK和LIRS的关系

```text
CLOCK：单环 + 单bit（ref）           —— 无频率语义
LIRS：IRR 精确排序 + LIR/HIR 集合    —— 强效果，高开销
CLOCK-Pro：单环 + 双bit（ref, test）+ 懒惰晋升 —— 中间点
```

**懒惰晋升（lazy promotion）**：与 SLRU/2Q 的"命中即晋升"不同，CLOCK-Pro 中对象在一次命中后仅设置 ref 位，**不移动位置**；只有在时钟指针扫过且 ref=1 时（test 阶段）才晋升——用时间换取低移动开销。这一思想在 2023-2024 年的 S3-FIFO/SIEVE 中以 FIFO 形式复兴（见 [01.04 学习驱动缓存算法](../01.04-学习驱动缓存算法/README.md) 第 10 节）。

### 1.3 算法结构

缓存组织为单循环链表，每个页携带两个位：

- **ref**：自上次时钟扫描以来是否被访问
- **test**：是否处于"测试期"（候选晋升状态）

页分两类：

- **test 页**：处于晋升测试中的页（冷页被二次访问后）
- **非 test 页**：普通驻留页

另维护 **Ghost List**（幽灵队列）：最近被淘汰页的标识（无数据，LRU），其命中用于调整参数（类似 ARC 的 B1/B2 反馈）。

### 1.4 工作流

**命中**：

- 页在缓存中：置 ref=1；若已在 test 状态则保持
- 页在 Ghost List：说明冷页被重用 → 按反馈调整时钟扫描力度

**miss 准入**：

1. 有空闲：插入时钟当前位置前，ref=0, test=0
2. 无空闲：扫描指针前进，逐页检查：
   - ref=1：清为 0，继续（second chance）
   - ref=0 且 test=1：完成晋升测试 → 该页保留，但其 test 清 0（转为普通页）；继续扫描找牺牲者
   - ref=0 且 test=0：选为牺牲者驱逐
3. 被二次访问的冷页：置 test=1 进入测试期

**关键不变式**：时钟扫描一圈内，test 页要么完成晋升（经受住考验），要么与牺牲者同等竞争——实现"低频页延缓驱逐、高频页加速驻留"。

### 1.5 性能特征

- **吞吐**：无链表移动，指针旋转为顺序访问，缓存友好（对比 LRU 的随机链表指针追逐）
- **扫描抵抗**：扫描页只获得一次 second chance，test 机制阻止其长期驻留
- **参数自适应**：Ghost List 命中率驱动冷/热页目标比例，无需手动调参（沿用 ARC 的反馈框架）
- **实践**：Solaris 内核（ARC 之外的选择）、部分嵌入式数据库缓冲池

## 2. LHD：最大化命中密度

### 2.1 设计动机

传统替换算法假设"所有对象等值"——驱逐决策只看未来被访问的可能性（LRU/LFU/CLOCK），不看对象占用的空间成本。现实中对象大小差异巨大（Web 对象 1KB-10MB、CDN 对象更大），驱逐一个大对象腾出 10MB 与驱逐一个小对象腾出 4KB，为后续对象提供的"容纳能力"完全不同。

**LHD（Least Hit Density，Beckmann et al., NSDI 2018）**：驱逐"期望命中数 / 占用空间"最低的对象，即最大化单位空间的期望命中贡献。

### 2.2 命中密度定义

对对象 $x$，定义：

$$HD(x) = \frac{E[\text{未来一段时间 } x \text{ 的命中次数}]}{size(x)}$$

驱逐决策：$\arg\min_x HD(x)$。

**与机会成本的关系**：驱逐 $x$ 腾出的空间可接纳新对象流；LHD 选择"单位空间期望命中最少"的对象，等价于最大化腾出的空间所能服务的新命中——这是缓存决策的机会成本视角。

### 2.3 预测模型

LHD 用**条件概率模型**估计未来命中：特征包括

- **最近访问间隔（recency）**：时间局部性的直接信号
- **历史命中次数（frequency）**
- **对象大小（size）**

模型形式（简化）：假设命中间隔服从某种分布（如指数/重尾），用历史访问统计拟合"再活 $t$ 时间内的期望命中次数"。工程实现中，LHD 用分段常数近似（recency × frequency × size 的直方图桶）保证 O(1) 查询。

### 2.4 与GDSF的关系

GDSF（Greedy Dual Size Frequency，Cherkasova 1998）是 Web 缓存经典算法，其优先级为：

$$priority(x) = \frac{L + F(x)}{size(x)^\alpha}$$

其中 $L$ 为通胀因子（全局时钟，类似 GD 系列的"年龄"基线），$F(x)$ 为频率加权。LHD 与 GDSF 共享"频率/大小加权"骨架，差异在于：GDSF 用启发式加权，LHD 用**预测模型的期望命中数**作为分子，并有 NSDI 论文级的系统性评估（对多种真实 trace，LHD 相对 LRU/GDSF/LFU 有稳定收益，对大小异构负载收益最大）。

## 3. 两种算法的对比与统一视角

| 维度 | CLOCK-Pro | LHD |
| ---- | --------- | --- |
| 决策信号 | ref/test 位（访问证据） | 期望命中密度（预测） |
| 对象大小感知 | 否 | 是（核心） |
| 数据结构 | 单环 + 幽灵队列 | 分桶优先级结构 |
| 开销 | 极低（CLOCK 级） | 中（分桶与模型更新） |
| 理论属性 | 近似 LIRS 行为 | 贪心机会成本最优的一步近似 |
| 最佳场景 | 均匀大小、扫描混合负载 | 大小异构（Web/CDN） |

**统一视角**：两者都是"**证据累积 → 驱逐决策**"框架的实例——CLOCK-Pro 用硬件风格的比特位累积访问证据（工程极简），LHD 用统计模型累积命中期望（决策最优）。S3-FIFO（2023）与 SIEVE（2024）证明前者的简化空间仍有红利；学习型算法（LeCaR/3L-Cache）则是后者的学习增强版。

## 4. 应用场景

- **CLOCK-Pro**：操作系统页缓存候选（实现简单+扫描抵抗）、嵌入式/受限环境
- **LHD**：CDN/对象缓存（大小异构极端）、Web 缓存层、混合存储介质缓存（空间成本即介质成本）
- **组合思路**：TinyLFU 准入 + CLOCK-Pro 主体（频率证据 + 懒惰晋升）；LHD 驱逐 + SLRU 分段（密度决策 + 扫描隔离）
