## 1. 概述

**S3-FIFO**（SOSP 2023）与 **SIEVE**（USENIX NSDI 2024）是 2023-2024 年缓存替换领域最重要的两个"返璞归真"式工作：它们证明**仅用 FIFO 队列 + 极简元数据**即可达到甚至超越 ARC/W-TinyLFU 的命中率，同时获得 LRU 难以企及的吞吐、扩展性与闪存友好性。两者是对"复杂自适应算法必然更优"这一隐含假设的直接挑战，也是评估学习型缓存（[01.04](../01.04-学习驱动缓存算法/README.md)）收益时必须先击败的非学习基线。

## 2. S3-FIFO：三个静态 FIFO 队列

### 2.1 设计动机

FIFO 被长期低估，作者（Yang, Yue, Rashmi 等，CMU/Emory/Pelikan）指出 FIFO 具有四个被忽视的性质：

1. **简单**：无链表移动、无指针追逐，代码量小、bug 少
2. **快速**：O(1) 且常数极小；队列操作是顺序访问，缓存友好
3. **可扩展**：FIFO 队列天然适合分片/无锁并发（队头队尾操作）
4. **闪存友好**：FIFO 的写模式是**顺序的**，与 SSD/FMD 的块擦写语义匹配；LRU 的随机写导致写放大

FIFO 的唯一问题是 miss ratio 高。S3-FIFO 的洞察：**高 miss ratio 不是因为 FIFO 的队列结构，而是因为缺乏准入控制**——一次性访问对象（one-hit wonders，如扫描、爬虫、预热请求）进入缓存后立即驱逐了热数据。只要用一个小队列过滤掉 one-hit wonders，FIFO 的命中率就逼近最优。

### 2.2 算法结构

三个静态 FIFO 队列 + 每对象 2-bit 饱和计数器：

```text
[ S 小队列（10%） | M 主队列（90%） ]   G 幽灵队列（仅存 key，容量 ≈ M）
  ↑ 新对象从这里进入  ↑ 经受过考验的对象   ↑ S 中淘汰对象的幽灵
```

- **S（Small/Probationary）**：新对象入口；10% 容量（作者用 10 个 trace 实验验证 10% 泛化良好）
- **M（Main/Second-Chance）**：长期驻留区；对象在 S 中被再次访问（访问计数 > 0）则晋升
- **G（Ghost）**：S 中淘汰对象的 key 历史，容量与 M 相同；G 命中可触发 M 调整（提高驱逐精度）
- **2-bit 饱和计数器**：取值 0-3，记录对象被访问次数（封顶 3），是每个对象唯一的元数据

### 2.3 读写流程

**读命中**（对象在 S 或 M 中）：

- 原子地递增该对象的访问计数器（封顶 3）
- **不移动对象位置**（与 LRU 的关键区别，与 CLOCK-Pro 的懒惰晋升同族）

**写（miss）**：

1. 新对象插入 S 头部，计数器 = 0
2. S 溢出时，从 S **尾部**取对象：
   - 计数器 = 0（从未被访问）→ 放入 G 头部（幽灵化），淘汰出缓存
   - 计数器 > 0（经受住考验）→ 晋升到 M 头部
3. M 溢出时，从 M **尾部**扫描：
   - 计数器 = 3（访问 ≥3 次，最热）→ 保留，计数器降为 2，指针继续（second chance）
   - 计数器 < 3 → 驱逐
4. G 溢出从 G 尾部丢弃；G 的命中统计可用于反馈（如调整 S 比例，论文保持静态也足够好）

### 2.4 准入过滤的统计学基础

设 one-hit wonders 占比为 $r$（Web 缓存中常达 60-80%）。无准入控制时，这些对象平均占用缓存约 $r \cdot k$ 个位置后才被驱逐。S 队列的过滤效果：

- S 容量 $s = 0.1k$，对象在 S 中驻留时间短（快速流过）
- 一次性对象在 S 中几乎必然以计数 0 离开，**被 G 吸收而不触碰 M**
- 热对象只需在 S 中再被命中一次即可进入 M

等价视角：S 是一个"微型快速考验区"，把"访问频率 ≥ 2"作为进入长期驻留的证据门槛——与 [2Q](../01.02-高级替换算法/01.02.08-SLRU与2Q算法.md) 的 FIFO 停留期、TinyLFU 的频率门槛同一谱系，但用纯 FIFO + 2bit 计数器实现，常数更小。

### 2.5 性能特征

- **Miss ratio**：在 10+ 个生产 trace（CDN、块存储、KV 等）上与 ARC、2Q、W-TinyLFU 打平或更优；扫描负载显著更优
- **吞吐**：显著高于 LRU/ARC（无链表移动；元数据操作少 3-5 倍）
- **并发扩展**：分片队列下近线性扩展（LRU 的分片需跨片迁移热对象）
- **闪存友好**：顺序写模式降低 SSD 写放大与延迟尾
- **工程成本**：核心逻辑 ~100 行 C 代码；已集成进 Cachelib（Meta 开源缓存库）

## 3. SIEVE：单队列懒惰晋升

### 3.1 设计动机

S3-FIFO 仍需维护三个队列；SIEVE（Zhang et al., ATC 2024）追问："**最少需要多少结构？**"答案：**一个 FIFO 队列 + 每对象一个 visited 位 + 一个驱逐指针**。SIEVE 的全部实现约 30 行 C 代码，却是当前 Web 缓存负载上最强的非学习算法之一。

### 3.2 算法结构

```text
队头（最旧）                              队尾（最新）
[ v=1 ][ v=0 ][ v=1 ][ v=1 ]...[ v=0 ][ v=0 ]← 新对象从这里入队
   ↑
  hand：驱逐指针，从队头向队尾扫描
```

- **单 FIFO 队列**：对象按插入顺序排列，新对象入队尾
- **visited 位**（1 bit/对象）：命中时置 1；不做任何移动
- **hand 指针**：驱逐时从队头向队尾扫描

### 3.3 工作流程

**命中**：将对象 visited 位置 1（O(1)，无移动）

**miss 且需驱逐**：

1. hand 指向的对象 visited = 0 → 驱逐之
2. visited = 1 → 清 0，hand 后移（"再给一次机会"——lazy promotion 的退化形式：不清除对象访问权，只是推迟驱逐）
3. hand 到达队尾后回到队头

**准入**：新对象直接入队尾，visited = 0。

### 3.4 与 CLOCK 的对比

SIEVE 与 CLOCK 常被类比，但有关键差异：

| 维度 | CLOCK | SIEVE |
| ---- | ----- | ----- |
| 结构 | 循环链表 | FIFO 队列 |
| 遍历 | 指针循环旋转 | 单向扫描（hand 不回溯已扫区域直到队尾） |
| 晋升语义 | ref 位清 0 后下次再置才"保住" | visited 清 0 即完成 second chance，被扫过的对象在下轮驱逐线之前 |
| 代码量 | 中 | 极小 |
| 命中率 | 接近 LRU | 在 Web 负载上**优于 LRU、接近 ARC** |

SIEVE 的单向 hand 语义是其命中率优势的来源：被 hand 放过（visited 清 0）的对象要等 hand 绕完整圈才可能被驱逐——等价于"对象至少存活一个驱逐周期"，这比 CLOCK 的即时循环更保护近期活跃对象。

## 4. 与既有算法的谱系关系

```text
准入过滤思想：2Q(1994) → ARC(2003,自适应化) → TinyLFU(2017,频率化)
懒惰晋升思想：CLOCK(1960s) → CLOCK-Pro(2005) → SIEVE(2024,极简退化)
FIFO 复兴：   FIFO → S3-FIFO(2023,三队列+计数器+幽灵)
统一特征：    放弃"命中即移动"(LRU范式)，转向"证据累积+批量/懒惰更新"
```

S3-FIFO 与 SIEVE 共同验证了一个 2023 年后的设计共识：**缓存淘汰的元数据越少、更新越懒惰，吞吐与扩展性越好；只要保留"准入过滤"这一环，命中率损失可以被压缩到几个百分点以内**。

## 5. 实验对比

综合 SOSP'23 / ATC'24 论文的公开结果（不同 trace 有差异，量级供参考）：

| 算法 | 相对 LRU 的 miss ratio | 相对吞吐 | 代码复杂度 | 并发扩展 |
| ---- | ---------------------- | -------- | ---------- | -------- |
| LRU | 基准 | 基准 | 中 | 差（需分片迁移） |
| ARC | -5% ~ -10% | 0.6-0.8× | 高 | 差 |
| W-TinyLFU | -5% ~ -12% | 0.8× | 高 | 中 |
| **S3-FIFO** | -5% ~ -10% | **1.5-3×** | **低** | **好** |
| **SIEVE** | -3% ~ -8%（Web 负载） | 高 | **极低** | 好 |

注：命中率差距在 ±3% 以内时应优先选结构简单的算法（工程成本与风险更低）。

## 6. 实现要点

```python
# S3-FIFO 核心逻辑示意（简化版，完整实现见 s3fifo.com 开源仓库）
class S3FIFO:
    def __init__(self, capacity: int):
        self.s_cap = max(1, capacity // 10)   # S 占 10%
        self.m_cap = capacity - self.s_cap
        self.S = OrderedDict()   # key -> freq(0-3)
        self.M = OrderedDict()
        self.G = OrderedDict()   # 幽灵队列（仅 key）

    def get(self, key):
        if key in self.S:
            self.S[key] = min(3, self.S[key] + 1)
            return True
        if key in self.M:
            self.M[key] = min(3, self.M[key] + 1)
            return True
        return False

    def put(self, key):
        if self.get(key):
            return
        if len(self.S) >= self.s_cap:
            old, f = self.S.popitem(last=False)   # S 尾部（最旧）
            if f > 0:
                # 经受住考验 -> 晋升 M 头部；M 满则从 M 尾部驱逐（freq<3 者给第二次机会）
                if len(self.M) >= self.m_cap:
                    while True:
                        old_m, f_m = next(iter(self.M.items()))
                        del self.M[old_m]
                        if f_m < 3:
                            break
                        self.M[old_m] = f_m - 1   # freq=3 者保留但降频（second chance）
                self.M[old] = f
            else:
                # one-hit wonder -> 幽灵化
                self.G[old] = None
                self.G.move_to_end(old)
                if len(self.G) > self.m_cap:
                    self.G.popitem(last=False)
        self.S[key] = 0
        self.S.move_to_end(key)
```

> 该片段展示 S 准入与晋升决策路径；生产实现使用无锁队列与对象池（见 s3-fifo 开源实现）。

## 7. 应用场景

- **高吞吐代理/CDN 缓存**：S3-FIFO/SIEVE 的吞吐与闪存友好性是决定性优势（Meta Cachelib 已集成 S3-FIFO）
- **无锁并发缓存**：分片 FIFO 队列避免跨片热数据迁移
- **嵌入式/受限环境**：SIEVE 的 1bit 元数据在内存受限场景极具吸引力
- **学习基线**：任何学习型缓存论文/方案的必备对照组
