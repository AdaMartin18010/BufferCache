## 1. 概述：分区的三重目标

数据分区算法在三个相互制约的目标间取舍：

| 目标 | 含义 | 算法手段 |
| ---- | ---- | -------- |
| 均匀性 | 负载/数据量在分片间方差小 | 虚拟节点、加权分配 |
| 迁移最小 | 增删节点只移动 ~1/n 数据 | 一致性哈希、槽位迁移 |
| 单调性 | 节点增删不引起无关分片再分配 | 一致性哈希（优于取模） |

取模哈希牺牲迁移最小（全量迁移）；纯随机牺牲均匀性（见 §2 球箱模型）；一致性哈希以 O(log n) 查询代价换取三者平衡（Karger et al., STOC 1997）。

## 2. 分片数量的数学

### 2.1 球箱模型：随机放置的负载上界

将 N 个 key 随机投入 n 个分片（balls into bins），最忙分片的期望负载（Gonnet 1981；Mitzenmacher, "The Power of Two Choices in Randomized Load Balancing", TPDS 1996 综述）：

$$E[L_{max}] \approx \frac{\ln n}{\ln \ln n} \cdot \frac{N}{n} \quad (N \gg n \ln n)$$

含义：无虚拟节点的随机环放置，热点分片负载可达均值 $\ln n / \ln \ln n$ 倍——n=100 时约 4.2 倍（推导自经典球箱结果，B 级）。**工程含义：分片数 n 越大，相对热点越温和，但绝对管理成本上升。**

### 2.2 虚拟节点与方差缩减

给每物理节点分配 v 个虚拟点（Karger 论文 §4 分析），等价于把每物理节点的负载表示为 v 个独立子负载之和，方差缩减为单点的 $1/v$（推导自独立同分布求和的方差性质，B 级）：

$$\mathrm{Var}(L_{node}) = \frac{1}{v} \cdot \mathrm{Var}(L_{point})$$

经验法则（Karger 取 $v = 100\text{-}200$，C 级工程惯例）：$v \geq 10\ln n$ 时最大偏差以高概率控制在 20% 内。

### 2.3 Redis Cluster 的 16384 槽设计权衡

固定槽数 S=2^14 是三个因素的对撞点（Redis Cluster 规范，B 级）：

1. **心跳包**：每节点维护全集群槽位图，消息大小 ∝ S/8 字节（bitmap）= 2 KB——S=65536 则 8 KB，千节点集群的心跳风暴不可接受（Gossip 传播成本 ∝ n² × 消息大小）。
2. **迁移粒度**：槽是迁移原子单位，数据量/槽 = 总数据/S。S 太小 → 单槽过大，迁移窗口长；S 太大 → 元数据膨胀。
3. **哈希 tag**：按 `{}` 槽位共置，S 越大 tag 冲突概率越低但收益递减。

**推论**：自建分片层选择槽数 S 的经验公式：单槽目标数据量 $d_{slot}$ 满足迁移窗口约束 $d_{slot} / B_{migrate} \leq T_{window}$，得 $S \geq D / (B_{migrate} \cdot T_{window})$（推导自迁移吞吐模型，见 §3）。

## 3. 再平衡成本模型

### 3.1 增删节点的最小迁移量

| 方案 | 扩容（n→n+1）迁移比例 | 依据 |
| ---- | -------------------- | ---- |
| 取模 | 100% | $k \bmod n \neq k \bmod (n+1)$ 几乎必然 |
| 一致性哈希（含虚拟节点） | $\approx \frac{1}{n+1}$（期望） | 新节点弧段覆盖 ∝ 1/(n+1)（Karger 论文引理） |
| 固定槽（Redis Cluster） | $\frac{\text{迁出槽数}}{S}$，rebalance 时按权重分配 | 槽迁移命令计数 |

### 3.2 迁移的资源账（推导自迁移流水线，B 级）

迁移总时间由三段组成：

$$T_{migrate} = \underbrace{T_{dump}}_{\text{源端序列化}} + \underbrace{\frac{D_{slot}}{B_{net}}}_{\text{传输}} + \underbrace{T_{load}}_{\text{目标加载}}$$

资源占用特性：

- **源端**：fork（RDB 序列化）CPU 与 COW 内存峰值；迁移期间该分片 QPS 下降（单线程被迁移命令占用）。
- **目标端**：加载期 CPU；**迁移完成前源与目标双份内存**——集群总内存水位在迁移期间上升 $\Delta M = D_{migrating} \times (1 + 副本)$。
- **网络**：$B_{net}$ 受副本同步与业务流量竞争，大迁移应限速（`redis-cli --cluster reshard` 的 pipeline 与 delay 参数）。

### 3.3 迁移期间的一致性窗口

Redis Cluster 的槽迁移协议（Redis Cluster 规范 §8）保证迁移原子性：

1. 目标节点准备：`CLUSTER SETSLOT <slot> IMPORTING`（源端 `MIGRATING`）。
2. 逐 key 迁移：`MIGRATE key target` 在源端 DUMP + 目标端 RESTORE + 源端 DEL，**单 key 原子**。
3. 迁移中的 key 访问：客户端收到 `-ASK 3999 target`，向目标节点发 `ASKING` 后重试——**读写不重定向丢失**，但需客户端支持 ASK/MOVED 语义。
4. 槽关闭：`SETSLOT NODE` 广播新归属。

**窗口风险**：迁移中途客户端缓存的旧拓扑（MOVED 表）过期 → 短时重试风暴；迁移与故障转移并发 → 槽位归属争议（epoch 仲裁）。演练见 [07.09.04](../../07-运维与部署/07.09-弹性伸缩与自愈/07.09.04-分片级弹性伸缩与分区迁移.md) 与 TC-CLUS-008。

## 4. 热点分区的统计学刻画

热点不能凭感觉，用两个可测指标定义（项目经验模型，C 级）：

| 指标 | 定义 | 热点阈值（经验起点） |
| ---- | ---- | ------------------ |
| 槽负载倾斜度 | $S_{ratio} = \frac{P99\ 槽\ QPS}{P50\ 槽\ QPS}$ | >3 持续 15min |
| 槽数据倾斜度 | $S_{data} = \frac{\max\ 槽\ used\_memory}{median\ 槽\ used\_memory}$ | >2 且持续上升 |

到达过程建模为泊松（经典排队论假设，B 级）：key 访问独立时，单槽 QPS $\sim$ Poisson($\lambda_{slot}$)，热点概率 $P(\lambda_{slot} > c\bar\lambda) = e^{-\bar\lambda}\sum_{k>c\bar\lambda}\bar\lambda^k/k!$。**key 不独立时（key 关联访问，如用户+其订单）泊松假设失效，需按"访问簇"建模**——这是热点预测模型误差的主来源。

## 5. 跨分区操作的一致性边界

| 操作类型 | 支持度 | 机制 | 边界 |
| -------- | ------ | ---- | ---- |
| 单 key | 全支持 | 天然分区原子 | — |
| 多 key 同槽 | 支持 | hash tag `{}` 强制共置 | tag 设计侵入 key 命名 |
| 多 key 跨槽 | 不支持（Redis Cluster） | — | 应用层拆分 + 补偿 |
| 跨槽事务/Lua | 不支持 | — | 业务幂等或 Saga（[08.02](../../08-分布式架构/08.02-分布式事务/)） |
| 跨槽聚合查询 | 不支持 | 客户端聚合（mget 拆分） | 结果非快照一致（各分片时刻不同） |

**一致性边界推论**：跨槽聚合查询（如"全站计数"）的结果是**多个分区瞬时值的拼接**，不构成快照隔离语义。强需求时应走预计算（维护聚合 key）——与 [04.03 行业场景](../../04-架构设计/04.03-行业应用场景/) 的计数器模式一致。

## 6. 场景

1. **千 key 级小集群**：S 不必大；一致性哈希 + v=50 虚拟节点足够，迁移量 ~1/n。
2. **TB 级缓存池**：固定槽 + 每槽 ≤2GB（迁移窗口 ≤10min @ 4MB/s）；槽位图入心跳，控制 S ≤ 16384。
3. **倾斜治理**：S_ratio >3 时先查 key 关联性（访问簇），再考虑拆槽（sub-split 槽内迁移）或加副本读。
