# 02.03.08 以数据访问为中心的系统设计与 PG 18 解剖

> 系统扩展的两种范式：**control-centric**（计算/请求驱动，扩算力）vs **data-centric**（数据访问驱动，扩数据通路）。本文建立 data-centric 设计框架，以 PG 18.6+ 为解剖案例，并给出数据驱动扩展的判定与技术栈成熟度表。

## 1. 两种范式对比

| 维度 | Control-Centric | Data-Centric |
| ---- | --------------- | ------------ |
| 扩展单元 | 请求处理算力（无状态实例） | 数据分区与访问通路 |
| 状态处理 | 状态外置（缓存/DB） | 状态与计算同址或就近 |
| 一致性焦点 | 请求调度公平性 | 数据局部性与副本拓扑 |
| 典型技术 | HPA 副本伸缩 | 分区/再平衡/分层/亲和调度 |
| 缓存角色 | 旁路加速 | 数据访问路径的内生层 |

**data-centric 判据**（满足 ≥2 即优先 data-centric 设计）：① 数据量 >> 算力需求（TB 级+）；② 访问模式有强局部性（分区后可就近）；③ 数据移动成本 >> 计算移动成本（[05.01.06 §2.1](../../05-全栈分析/05.01-硬件层深度剖析/05.01.06-缓存系统三层结构与全链路Metric.md) 链路账：跨 AZ 1-3ms vs 同机 10ns——差 6 个数量级）；④ 扩展瓶颈在数据通路（I/O 饱和先于 CPU）。

## 2. PG 18 解剖：data-centric 缓存体系

PG 18（2025-09 起，含 18.x 补丁线至 2026-11 的 18.6+）的缓存体系是"数据库内生 data-centric 设计"的成熟案例：

| 层 | 组件 | data-centric 机制 | 成熟度 |
| -- | ---- | ----------------- | ------ |
| 查询结果缓存 | 计划缓存 + 结果缓存（扩展） | 同一查询的数据访问复用 | 计划缓存原生；结果缓存靠 pgmemcache 类扩展 |
| **缓冲池（核心）** | shared_buffers（[02.03.03](02.03.03-PostgreSQL-Shared-Buffer.md)） | 数据页的就近缓存，LRU/Clock-Sweep 管理 | ★★★ 生产 30 年 |
| I/O 层 | **异步 I/O（AIO，18 新）** | 批量提交/完成喂满 MLP（05.01.6 §2.3） | ★★☆ 18 新特性，快速成熟 |
| OS 协作 | 页缓存双缓冲 + pg_buffercache（18 可逐出） | OS 层二级缓存+主动干预 | ★★★ |
| 外部扩展 | pg_prewarm/缓存外部化 | 预热与外部缓存边界（[02.03.07](02.03.07-PostgreSQL18缓存能力与外部缓存边界.md)） | ★★★ |

**data-centric 要点**：PG 的优化器-缓存协同（ANALYZE 默认 BUFFERS 使计划感知缓存状态）是"数据访问驱动"的完整闭环——**缓存状态成为查询计划的输入**，而非旁路。这与 Redis 式"外部缓存 + 应用维护"形成范式对照（本项目 F19 指纹的深层依据）。

## 3. 数据驱动扩展的三模式

| 模式 | 机制 | 案例 | 指纹 |
| ---- | ---- | ---- | ---- |
| 分区扩展 | 数据按访问域切分，扩分区即扩容量与吞吐 | PG 分片（Citus）/Redis Cluster 槽 | F17 |
| 分层扩展 | 按热度在物理层级间迁移（05.01.6 链路） | PG 双缓冲/LLM KV 分层/CXL 内存池 | §8.4 判据 |
| 亲和扩展 | 计算调度到数据所在（data locality） | Spark 分区调度/网格 EntryProcessor/LLM P-D 分离的 KV 亲和路由（[04.03.17 §3](../../04-架构设计/04.03-行业应用场景/04.03.17-大模型推理缓存部署实践.md)） | F23-d |

## 4. 技术栈成熟度分级（数据通路层）

| 技术 | 原理一句话 | 成熟度（2026-11） | 生产建议 |
| ---- | ---------- | ----------------- | -------- |
| io_uring | 共享环形队列免系统调用批量 I/O | ★★★（Linux 7.x 持续增强，FUSE 6.17） | 默认采用（[05.02.04](../../05-全栈分析/05.02-网络通信层/05.02.04-io_uring异步IO.md)） |
| NVMe-oF | NVMe 协议跨网络（RDMA/TCP） | ★★★ | 存算分离标配 |
| **CXL 内存池** | PCIe 一致性协议共享内存 | ★★☆（延迟 400-700ns 实测；PCIe 6.0/CXL 3.0 合规 2026） | 分层内存新层；先做缓存后做内存 |
| SPDK/DPDK | 用户态轮询绕过内核 | ★★☆（专用场景成熟） | 极端延迟 SLO 才付运维价格 |
| RDMA 单边读 | 远程内存直接读免 CPU | ★★★（Mooncake/NIXL 生产） | KV 池/存储分离采用 |
| GPU 直连存储（GPUDirect） | GPU 绕过 CPU 访问 NVMe/内存 | ★★☆（AI 场景成熟） | LLM 数据通路专用 |

## 5. 判定指纹（F24）

| 指纹 | 结论 | 锚点 |
| ---- | ---- | ---- |
| F24-a | 数据量>>算力+强局部性 → 范式 | data-centric 优先（本节 §1 判据） |
| F24-b | 缓存状态进查询计划 → 设计 | PG 18 式内生缓存（优于应用旁路维护） |
| F24-c | 跨级移动数据成本>移动计算 → 调度 | 计算亲和调度（§3 第三模式） |
| F24-d | 分层扩展的层数上限 → 判定 | 每级准入判据成立才加层（04.03.15 §8.5） |
