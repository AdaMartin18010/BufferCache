## 1. 概述

2019-2025 年，存储栈发生了三层并行重构：**设备语义重构**（ZNS 分区接口、KV 下沉）、**I/O 路径重构**（io_uring、SPDK 内核旁路）、**内存层级重构**（远程内存、CXL）。这些变化的共同主题是——**每一层都在重新定义"缓存应该放在哪里、以什么粒度、按什么延迟账管理"**。本文是 [02.04 现代内核缓存机制](./README.md) 的姊妹篇，聚焦存储栈侧的新机制及其对缓存设计的影响。

## 2. ZNS SSD：分区命名空间

### 2.1 设计动机

传统块接口 SSD（FTL 隐藏内部结构）存在两个问题：

1. **写放大**：FTL 的异地更新 + GC 导致实际写入放大 2-4 倍，缩短寿命
2. **延迟不可控**：GC 暂停造成尾延迟尖峰，与缓存层的延迟 SLA 冲突

ZNS（Zoned Namespaces, NVMe 1.4+ 标准，2020 起商用）把**地址管理责任交还主机**以换取可预测性。

### 2.2 Zone 语义

- LBA 空间划分为大小固定的 **zone**（如 128MB-1GB）
- 每 zone **顺序写**：`zone start → zone end`，不可原地更新
- 写满后须显式 **reset** 才能复用（擦除粒度对齐闪存块）
- zone 可处于 Empty / Implicitly Opened / Explicitly Opened / Full / Closed / Offline 状态

**软件栈适配**：F2FS（原生 zoned mode）、RocksDB（ZenFS 后端）、Western Digital 的 zoned 生态。主机软件（而非 FTL）决定数据放置与 GC 时机——**垃圾回收从"设备黑盒"变成"主机可调策略"**。

### 2.3 对缓存层的影响

1. **写模式约束传导**：缓存的 write-back 落盘策略必须尊重 zone 顺序写语义（日志结构化缓存天然适配；随机写小对象需要 LSM-tree 类合并）
2. **驱逐策略与擦除周期联动**：缓存容量规划需考虑 zone reset 的开销窗口（类似 [MGLRU](./README.md) 的交换设备感知）
3. **延迟可预测性收益**：无 FTL GC 暂停后，缓存分层中的 SSD 层延迟方差收窄，**分层准入判据**（$t_{reload} < t_{reprefill}$，见 [04.03.15](../../04-架构设计/04.03-行业应用场景/04.03.15-大模型推理缓存架构.md) §8.4）可用更紧的界
4. **寿命账**：写放大降低 2-4 倍 ⇒ 缓存层可以更激进地使用 SSD 做写缓存（写寿命预算翻倍）

## 3. KVSSD：键值接口下沉

- **概念**：SSD 固件直接暴露 KV 接口（`store(key, value)` / `retrieve(key)`），主机不再管理 LBA 映射，设备内部完成哈希索引与 GC
- **代表**：Samsung KV-SSD（OpenMPDK 生态）、SNIA KV API 标准
- **对缓存层的意义**：
  - **缓存下沉**：设备本身即 KV 缓存（带 TTL 语义扩展），主机缓存层退化为"热缓存 + 设备大缓存"两级结构
  - **一致性简化**：对象级原子性替代块级写序维护
  - **容量账**：4TB+ 设备做"冷 KV 层"使三层缓存（DRAM → 主机 SSD → KVSSD）成为云厂商降本方案（对应 [04.05 成本优化](../../04-架构设计/04.05-成本优化/) 的存储分层成本模型）
- **代价**：对象大小限制（value 通常 ≤ 2MB-4MB）、GC 与主机层的写模式耦合仍需协同

## 4. io_uring 深入

### 4.1 已覆盖基础

[05.02.04 io_uring异步IO](../../05-全栈分析/05.02-网络通信层/05.02.04-io_uring异步IO.md) 与 [02.04 README](./README.md) §6.3 已介绍：环形提交/完成队列、共享内存、一次系统调用批处理 I/O。

### 4.2 高级特性（2023-2025）

| 特性 | 内核版本 | 说明 | 缓存场景价值 |
| ---- | -------- | ---- | ------------ |
| **Registered Buffers** | 5.1+ | 预注册固定内存，避免逐 I/O 的 get_user_pages | 缓存页池常驻注册，降低 pin/unpin 开销 |
| **Linked SQEs** | 5.3+ | 同一 ring 内 I/O 链式依赖（如 read→write） | 缓存回填（miss 后读盘+写缓存原子链） |
| **Multishot Accept/Recv** | 6.0+ | 一次提交持续接收（边缘触发替代轮询完成队列） | 缓存服务器高并发连接削减完成事件处理 |
| **IORING_OP_READ_MULTISHOT / recv bundles** | 6.x+ | 大数据流自动分段完成 | 大 value 缓存读减少提交次数 |
| **Uncached Buffered I/O** | 6.14+ | 异步接口覆盖 buffered 路径（内核页缓存参与） | 页缓存与异步应用 I/O 的桥接（见 02.04 README） |
| **Big SQ/CQ rings & NAPI busy poll 协同** | 6.x | 深度队列配合轮询减少中断 | 缓存节点 P99 延迟优化 |

**设计启示**：io_uring 使"内核页缓存 + 异步应用"组合可行——缓存系统不必在"内核缓冲"与"用户态缓冲"（DPDK/SPDK 路线）之间二选一，而是按延迟预算分层选择。

## 5. SPDK：用户态存储栈

- **定位**：Intel 发起的用户态存储开发套件：轮询模式 NVMe 驱动、用户态块层（bdev）、vhost 目标、BlobFS
- **原理**：UIO/VFIO 直接映射设备队列到用户态，**绕过内核调度、中断与系统调用**；单核轮询可达百万 IOPS
- **缓存系统用法**：
  - 缓存节点内核旁路：Redis/缓存代理直接落盘到用户态驱动，消除内核存储栈的上下文切换与拷贝（与 [05.02.03 零拷贝](../../05-全栈分析/05.02-网络通信层/05.02.03-零拷贝技术对比.md) 配合）
  - vhost-blk/scsi 向虚拟机暴露加速存储（云缓存实例）
- **代价**：独占 CPU 核（轮询）、无页缓存（应用自建缓冲）、工程复杂度高
- **与 io_uring 的分工**：SPDK 追求极致 IOPS 与端到端用户态；io_uring 追求通用性与内核特性协同（页缓存、文件系统）。2025 年的共识：**大多数缓存落盘场景 io_uring 已足够，SPDK 留给专用高性能缓存设备**

## 6. Far Memory：远程内存作为缓存层

内存解聚合（memory disaggregation）把集群空闲内存池化为"远内存"层，本机 DRAM 不足时换页/迁移到远程节点（RDMA 访问，~2-5μs RTT vs 本地 DRAM ~100ns、SSD ~100μs）。缓存视角：**远内存是 DRAM 与 SSD 之间的天然新层级**。

### 6.1 透明换页路线

- **Infiniswap**（NSDI 2017）：块设备接口的远程换页先驱，按需拉页 + 预取，把远程内存呈现为 swap 分区
- **FastSwap / Leap**（EuroSys 2020 / ATC 2020）：内核交换路径优化 + **远程内存预取**（Leap：页故障簇的即时预取，隐藏网络 RTT）
- **内核集成**：TPP（Transparent Page Placement, ASPLOS 2022）在 Linux 中按访问热度在 NUMA/CXL/远程层间自动迁移——与 [DAMON 自适应分层](./README.md) §4.4 同族

### 6.2 应用集成路线（AIFM）

- **AIFM**（OSDI 2020, Ruan/Schwarzkopf/Aguilera/Belay）：放弃透明性，把"远程化"语义暴露给应用（remoteable 指针/对象），运行时负责换入换出、**应用感知预取**、并发控制与故障疏散
- **收益**：透明换页的页粒度（4KB）在远程 RTT 下放大开销；应用级粒度（对象/请求级）可按语义批量预取，性能提升一个量级
- **启示**：与 [04.03.15](../../04-架构设计/04.03-行业应用场景/04.03.15-大模型推理缓存架构.md) 的 LLM KV Cache 分离架构**完全同构**——Mooncake 的"以 KV 为中心调度"就是 AIFM 思想在推理缓存上的实例化

### 6.3 预取与异步性

- **Leap**：利用换页故障的空间/时间局部性做即时预取
- **Hermit**（NSDI 2023）：反馈驱动的异步性——根据应用进展动态调整预取与同步策略，吞吐与延迟兼顾
- **Polaris** 等 CXL 内存侧预取：设备端预取隐藏 CXL 延迟

### 6.4 延迟账与准入判据

远内存层的延迟账（与 [04.03.15](../../04-架构设计/04.03-行业应用场景/04.03.15-大模型推理缓存架构.md) §8.4 的判据一致）：

| 层级 | 访问延迟 | 容量 | 带宽 |
| ---- | -------- | ---- | ---- |
| 本地 DRAM | ~100ns | 100-500GB | 100-400GB/s |
| CXL 内存 | ~170-300ns | TB 级 | 50-200GB/s |
| 远内存（RDMA） | ~2-5μs | 池化 PB 级目标 | 25-100GB/s |
| 本地 NVMe | ~100μs | TB 级 | 5-14GB/s |
| 远端存储 | ~500μs-数ms | EB 级 | GB/s 级 |

远内存相对 SSD 的延迟优势（20-50×）与容量成本优势使其成为"内存不足但延迟敏感"负载的首选扩展层；预取质量（Leap/Hermit）决定实际有效带宽。

## 7. 对缓存架构设计的启示

| 技术 | 对缓存设计的直接启示 |
| ---- | -------------------- |
| ZNS | SSD 缓存层采用日志结构化/LSM 落盘；驱逐与 zone reset 窗口联动 |
| KVSSD | 设备即冷缓存，主机缓存退化为热层；对象粒度一致性替代块级 |
| io_uring 高级特性 | 注册缓冲区 + linked SQE 实现"miss→读盘→回填"原子链 |
| SPDK | 极致场景（用户态端到端）放弃页缓存；评估独占核成本 |
| Far memory | DRAM 与 SSD 之间新增缓存层级；应用感知粒度优于透明页粒度 |
| CXL（衔接 [02.02.06](../../02-系统实现/02.02-CPU缓存架构/02.02.06-新型存储介质缓存架构.md)） | 机架级分层由 DAMON/TPP 自动化管理 |

统一主题：**存储栈的每一层重构都在把"缓存"从单一 DRAM 池扩展为多介质、多粒度、有明确延迟账的层级体系**——这正是经典分层缓存理论（本项目 [01-理论基础](../../01-理论基础/)）在 2025 年硬件现实上的落地。
