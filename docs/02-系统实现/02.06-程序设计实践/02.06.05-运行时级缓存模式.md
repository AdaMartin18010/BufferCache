# 02.06.05 运行时级缓存模式

> 语言运行时的内存管理特性决定本地缓存的形态选择。按运行时梳理缓存模式的约束与最佳实践。

## 1. JVM（Java/Kotlin/Scala）

| 机制 | 说明 | 缓存含义 |
| ---- | ---- | -------- |
| 堆内缓存 | 对象图在 GC 堆 | Caffeine 默认；大堆（>4GB）GC 停顿风险——G1/ZGC 缓解但吞吐降 |
| **堆外缓存** | DirectByteBuffer/Unsafe（off-heap） | GC 免疫；手动管理序列化（[03.01.13 权衡](../../03-Redis组件/03.01-核心数据结构/03.01.13-序列化编码与内存布局权衡.md)）；Ehcache/MMap 模式 |
| 大页与 NUMA | -XX:+UseLargePages + NUMA-aware 分配 | 堆外缓存 + HugePages 降 TLB miss（[02.05.2](../02.05-系统级优化/02.05.02-HugePages大页内存.md)） |
| 虚拟线程（JDK 21+） | 百万级轻量线程 | 缓存客户端的阻塞调用成本骤降——池大小可再压（[05.03.6 §4](../../05-全栈分析/05.03-控制流分析/05.03.06-缓存交互动态设计.md) 并发模型联动） |

**模式**：热数据 Caffeine（堆内）+ 大值/大容量 off-heap（Ehcache OffHeap 或自研 DirectBuffer 池）；堆外命中需反序列化（~μs 级，[03.01.12 复杂度](../../03-Redis组件/03.01-核心数据结构/03.01.12-数据类型操作算法与复杂度论证.md)）。

## 2. Go

| 机制 | 缓存含义 |
| ---- | -------- |
| GC 压力 | 大本地缓存（GB 级）引发 GC 扫描开销——freecache/ristretto/bigcache 的 **分片+无指针设计** 规避（避免扫描） |
| GMP 亲和 | goroutine 的本地缓存（per-P shard）天然无锁友好 |
| arena（实验） | Go arena 提案成熟后堆外管理更可控（跟踪中） |

## 3. Python

| 机制 | 缓存含义 |
| ---- | -------- |
| GIL | 计算型缓存逻辑（压缩/序列化）阻塞全线程——缓存线程池隔离 |
| `__slots__` | 缓存条目类省内存（无 **dict**） |
| C 扩展缓存 | 核心热路径下沉 C/Rust（或直接用 Redis 客户端的 hiredis 解析） |

## 4. Node.js/事件循环

异步客户端 mandatory（[03.06.7](../../03-Redis组件/03.06-网络通信/03.06.07-客户端连接与重试行为矩阵.md)）；进程内缓存注意 worker 多进程不共享（需外部缓存或共享内存）。
