## 1. 概述与复杂度分级

Redis 官方为每条命令标注大 O 复杂度（redis.io/commands，B 级权威）。本文按三档组织：

| 档位 | 含义 | 工程态度 |
| ---- | ---- | -------- |
| O(1) | 与数据规模无关 | 任意调用频率 |
| O(log N) | 对数（跳表/树/哈希扩容） | 百万级元素仍 <20 步 |
| O(N) 及以上 | 线性或更差 | 必须评估 N 的规模上限 |

**编码升级突变**：小对象用紧凑编码（listpack/intset/quicklist 节点），达到阈值升级（hashtable/skiplist/hashtable），**同一命令复杂度跨档跳变**（如 HGETALL 在 listpack 编码下是 O(N) 顺序扫描，在 hashtable 编码下是 O(N) 哈希遍历——同为 O(N) 但常数差 5-10 倍，C 级实测经验）。

## 2. String 操作

| 操作 | 复杂度 | 算法要点 | 出处 |
| ---- | ------ | -------- | ---- |
| SET/GET/DEL | O(1) | 哈希定位；GET 带 key 过期惰性检查 | 官方文档 |
| APPEND | O(1) 均摊 | SDS 预分配（<1MB 翻倍），均摊后摊还 O(1) | SDS 设计（03.01.01） |
| INCR/DECR | O(1) | 共享整数对象直改（0-9999 预分配），解析+进位 | 官方文档 |
| GETRANGE/SETRANGE | O(N) | 内存拷贝 N 字节 | 官方文档 |
| STRLEN | O(1) | SDS 长度字段 | 官方文档 |
| SETEX/PSETEX | O(1) | SET + PEXPIRE 合并为一次字典操作 | 官方文档 |

**bigkey 放大**：value 10MB 时 GET 的 O(N) 拷贝 = 10MB 内存搬运 + 网络传输 + 客户端解析，三处常数放大（05.04 数据流有账）。

## 3. Hash 操作

| 操作 | 复杂度 | 要点 |
| ---- | ------ | ---- |
| HSET/HGET/HDEL | O(1)（hashtable）/ O(N)（listpack，N=字段数） | 编码阈值 hash-max-listpack-entries 128 / value 64B（8.x 默认） |
| HGETALL/HDEL(全) | O(N) | 遍历全部字段 |
| HINCRBY | O(1) | 同 INCR |
| HEXISTS | O(1) | 哈希查找 |

**编码突变点**：字段数超 128 → listpack 转 hashtable（03.01.02 dict 渐进 rehash 期间的摊还成本）；**边界抖动**（在阈值附近增删字段导致反复转换）是隐藏的 CPU 毛刺源。

## 4. List 操作

| 操作 | 复杂度 | 要点 |
| ---- | ------ | ---- |
| LPUSH/RPUSH/LPOP/RPOP | O(1) 每元素 | quicklist 头尾节点操作；多元素批量版本 O(N) |
| LLEN | O(1) | 长度计数器 |
| LINDEX | O(N) | 跨节点定位：先节点索引（quicklistNode 数组均摊 O(N/k)）再节点内 listpack 定位 |
| LRANGE | O(S+N) | S=偏移跨度内节点数，N=返回元素数 |
| LSET | O(N) | 同 LINDEX 定位 |

**bigkey 放大**：百万元素列表 LINDEX 尾部 = 遍历 ~节点数；LREM key 0 value 全量扫描 O(N) 且逐元素 memcmp。

## 5. Set 操作

| 操作 | 复杂度 | 要点 |
| ---- | ------ | ---- |
| SADD/SREM/SISMEMBER | O(1)（hashtable）/ O(N)（intset，N=元素数，二分查找 O(log N) 但插入移动 O(N)） | intset 仅整数且 <512（set-max-intset-entries） |
| SMEMBERS | O(N) | 全集合输出 |
| SPOP | O(1) | hashtable 随机槽位 |
| SINTER | O(N×M) | 小集合遍历 × 大集合查询；8.x 对小集合有优化 |
| SUNION/SINTERSTORE | O(N) / O(N+M) | 结果集构造另计 |

## 6. ZSet 操作

| 操作 | 复杂度 | 要点 |
| ---- | ------ | ---- |
| ZADD | O(log N) | skiplist 插入 + dict 索引双写 |
| ZRANGE (索引) | O(log N + M) | 定位起始 + M 步遍历 |
| ZRANGEBYSCORE | O(log N + M) | 跳跃表按 score 层降搜索 |
| ZREM | O(log N) | 双结构删除 |
| ZINCRBY | O(log N) | 删除+重插（score 变更） |
| ZRANK/ZREVRANK | O(log N) | 跨度累加 |
| ZUNIONSTORE | O(N) + O(M log M) | 归并 + 目标集重建 |

**实现联动**：listpack 编码（小 zset）的 ZADD 是 O(N) 顺序插入（listpack 无索引）——编码阈值 zset-max-listpack-entries 128。

## 7. Stream 操作

| 操作 | 复杂度 | 要点 |
| ---- | ------ | ---- |
| XADD | O(1) | 尾部 radix tree 插入 + listpack 打包 |
| XLEN | O(1) | 计数器 |
| XRANGE | O(N) | 范围遍历 |
| XREAD（阻塞） | O(N) 数据 + 阻塞语义 | 事件循环注册阻塞客户端 |
| XDEL | O(1) | 墓碑标记 |
| XTRIM | O(N) | 按上限/最小 ID 裁剪 |

## 8. 操作放大：bigkey 交互分析

bigkey 的危害不是"大"，而是 **O(N) 操作在大 N 下的常数爆炸**（与 [04.04.05 大 Key 问题](../../04-架构设计/04.04-缓存问题与治理/04.04.05-大Key问题.md) 互补的算法视角）：

| 场景 | 操作 | N | 后果 |
| ---- | ---- | - | ---- |
| 100 万成员 set | SMEMBERS | 10^6 | 秒级阻塞 + 网络洪峰 |
| 10MB string | GETRANGE 0 -1 | 10^7 字节 | 单请求搬运 10MB |
| 50 万元素 zset | ZADD 单条 | log(5×10^5)≈19 | 正常——但 ZREMRANGEBYRANK 0 -1 清全表 = O(N log N) |
| 百万元素 list | LREM key 0 dup | 10^6 | 全扫描 + 内存移动 |

**评估公式**（推导自官方复杂度+实测常数，C 级）：操作耗时 ≈ 复杂度项 × 常数（哈希探测 ~10ns、指针追逐 ~5ns、memcmp 字节 ~0.1ns）。百万级 SMEMBERS ≈ 10^6 × (50ns 遍历+拷贝) ≈ 50ms——足以阻塞单线程 Redis 的百 ms 级窗口。

## 9. 场景

1. **排行榜**：ZADD/ZINCRBY O(log N) 高频安全；周榜重置用 ZREMRANGEBYRANK 分批。
2. **Feed 流**：list LPUSH + LRANGE 前 N 条；避免 LINDEX 深翻页。
3. **去重**：set SISMEMBER O(1) 天然适合；亿级分桶（[01.03.05](../../01-理论基础/01.03-分布式缓存算法/01.03.05-数据分片数学与再平衡模型.md) 分片）。
