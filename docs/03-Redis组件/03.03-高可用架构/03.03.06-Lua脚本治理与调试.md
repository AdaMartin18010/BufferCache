## 1. 脚本生命周期

```text
开发 → SCRIPT LOAD（得到 SHA1）→ 应用存 SHA1 → EVALSHA 调用
                                    ↓
              脚本变更 = 新 SHA1（旧 SHA1 可并存，滚动切换）
              下线旧版本 → SCRIPT FLUSH（整库清空，生产慎用）或自然过期
```

- **SHA1 vs 脚本体**：EVAL 每次传脚本体（网络与解析开销）；EVALSHA 传 20 字节摘要——生产一律 EVALSHA，应用侧缓存 SHA1。
- **redis.replicate_commands()**（7.x Function 之前的老接口）：脚本内显式声明写传播点（效果复制的旧式控制）。
- **Redis 7+ Functions**：Lua 脚本的"正式版"——命名、版本、载入即校验，替代游离的 EVALSHA 脚本库（官方方向，B 级）；新项目优先 Functions，EVALSHA 存量维护。

## 2. 性能模型

- **脚本内 redis.call 是函数调用而非网络往返**：脚本在 Redis 进程内执行，call 是同线程 C 调用——循环 1 万次 call 的耗时是每次 ~0.1-1μs（指针遍历+命令查找），不是 1 万次网络 RTT（常见误解）。
- **真实开销**：脚本编译一次缓存（evalsha 命中后零编译）；长脚本阻塞事件循环——**lua-time-limit**（默认 5s）只是慢脚本报警阈值，不中断执行（设计如此，B 级官方语义）。
- **实践上限**：脚本执行时间控制在 **1ms 内**（C 级项目经验；5ms 已会造成 P99 抖动），数据量相关的循环（SMEMBERS 遍历处理）必须先 `if #items > N then return end` 限幅。

## 3. 复制的正确性边界（effects 复制）

Lua 脚本在从库重放的不是脚本本身而是**脚本产生的写效果**（Redis 5.0+ effects 复制，B 级官方语义）。边界：

| 场景 | 行为 | 风险 |
| ---- | ---- | ---- |
| 确定性脚本（纯参数计算） | effects = 固定写集，安全 | 无 |
| **非确定性命令**（`TIME`、`RANDOMKEY`、`SPOP`、`SRANDMEMBER`） | effects 复制用**主库当时的实际结果** | 主从最终一致 ✓，但脚本多次执行结果不同（重试语义混乱） |
| `redis.set_repl(redis.REPL_NONE)` | 抑制传播（调试/临时态） | 从库数据漂移——生产禁用 |
| 脚本内 PUBLISH | 作为效果传播 | 从库也发布——订阅者收到重复（按 at-least-once 设计） |

**规则**：脚本内禁止用非确定性命令的返回值参与业务写路径（如 `local k = redis.call('RANDOMKEY')` 后写 k）——可重试性与可测试性破坏，且与 effects 复制叠加后行为难以推理。

## 4. 调试方法

```bash
# 1. 开发期：redis-cli --eval（脚本文件 + 参数分离语法）
redis-cli --eval myscript.lua key1 key2 , arg1 arg2

# 2. 生产排障：慢日志记录 EVALSHA 的耗时（slowlog 显示命令名与 SHA）
SLOWLOG GET 10

# 3. 函数版本（Functions）自带统计：FCALL 的 call 计数与错误率
INFO commandstats | grep -i fcall

# 4. 日志埋点：脚本内 redis.log(redis.LOG_NOTICE, '...')（写入 Redis 日志）
```

**SHA 反查**：`SCRIPT EXISTS <sha>` 确认已载入；应用侧必须维护 SHA1→脚本版本的映射表（否则生产事故时无法反查"这个 SHA 是什么逻辑"）。

## 5. 生产脚本审核清单

1. **时长限幅**：循环有界（数据量相关循环先取大小再判 `> N return`）；目标 <1ms。
2. **禁止命令**：`FLUSHALL/FLUSHDB/SHUTDOWN/CONFIG SET`（脚本内不可幂等恢复）；非确定性命令不入业务路径（§3）。
3. **错误处理**：`redis.call` 出错即中断（Lua 错误传播）；`redis.pcall` 捕获后继续——默认 call 即可，pcall 只在"部分失败可接受"时用。
4. **键命名**：脚本内 key 一律参数传入（`KEYS[i]`），硬编码 key 禁入（可测试性与多租户隔离）。
5. **版本管理**：Functions 命名+版本号；EVALSHA 脚本入代码库（脚本体即源码，SHA1 由 CI 计算校验）。
6. **变更流程**：脚本=代码，走 CR；禁止生产 `EVAL "现场拼脚本"`。

## 6. 场景

1. **库存扣减**：Lua（原子读判写）+ 限幅（单 SKU 库存，循环 ≤1）；详见 [04.03.01 秒杀](../../04-架构设计/04.03-行业应用场景/04.03.01-电商零售秒杀架构.md)。
2. **速率限制滑动窗口**：Lua 一次调用完成 ZREMRANGEBYSCORE+ZADD+ZCARD+PEXPIRE 四操作。
3. **批量任务**：Functions 库管理版本化脚本集（限流/去重/计数器），替代应用侧散落 EVALSHA。
