# 03.05.01 开源缓存技术全景图

> 跨项目的开源缓存技术全景：四大分类 × 治理归属 × 成熟度 × 选型指纹。与 [03.05 README](./README.md)（Redis 生态深描）互补——本文管"全景与横评"，README 管"单一生态纵深"。判定指纹 F22 已汇入决策图网。

## 1. 全景分类图

```text
开源缓存技术
├── 内存 KV 存储（远程缓存主力）
│   ├── Redis（AGPLv3 8.0+；功能最全）/ Valkey（LF，BSD，9.x 高性能 I/O）
│   ├── Dragonfly（BSL→Apache；多线程 C++，高吞吐宣称）/ KeyDB（BSD 多线程）
│   ├── Garnet（微软，MIT；.NET/RESP，VLDB 2026 论文）
│   └── Memcached（BSD；极简 KV，仍有大厂规模部署）
├── 分布式数据网格（计算+缓存一体）
│   ├── Hazelcast（IMDG；Java 生态，企业版为主）
│   ├── Apache Ignite（Apache 2.0；内存计算+持久化）
│   └── Infinispan（Red Hat；JGroups 通信，嵌入式/远程双模式）
├── 进程内缓存（本地一级）
│   ├── Caffeine（Java；W-TinyLFU 实现，事实标准）
│   ├── ristretto（Go）/ quick-cache（Rust）
│   └── STL 容器/自研（无统一治理）
├── CDN/边缘 开源（自建边缘层）
│   ├── Varnish（BSD；VCL 引擎，自建 CDN 首选）
│   └── Apache Traffic Server（Apache；雅虎遗产，大型部署）
└── 客户端/代理层
    ├── Envoy Redis 代理（CNCF；连接收敛/熔断，见 04.06.05）
    ├── Twemproxy（历史，静态分片）/ Codis（停更）
    └── redis-shake（阿里；异构同步/迁移工具，07.05.05 引用）
```

## 4. 前沿对齐（截至 2026-11）

- **治理归属成为选型第一维度**：Redis 许可变迁后，治理归属（LF/Apache/厂商）比性能对比更先被审查——与 [04.03.16 §2.1](../../04-架构设计/04.03-行业应用场景/04.03.16-云原生缓存趋势与实践.md) 云默认引擎结论一致。
- Garnet 以 VLDB 2026 论文确立学术地位；Valkey 9.x I/O 线程重构为 BSD 路线性能标杆。
- 数据网格类（Ignite/Hazelcast）在"缓存+计算融合"场景（金融风控/实时特征）保持生态位，通用缓存选型不优先（复杂度价格）。
