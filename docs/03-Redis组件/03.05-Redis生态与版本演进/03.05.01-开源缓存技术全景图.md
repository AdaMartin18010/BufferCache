## 4.5 数据网格深描（Hazelcast/Ignite/Infinispan）

> 数据网格与内存 KV 的本质区别：**缓存与计算同址**（compute-where-data-is），而非"把数据搬到计算侧"。

| 维度 | Hazelcast | Apache Ignite | Infinispan |
| ---- | --------- | ------------- | ---------- |
| 核心模型 | IMDG（分布式数据结构+执行器） | 内存计算平台（SQL+键值+持久化） | 缓存平台（JGroups 通信，嵌入式/远程） |
| 计算能力 | 分布式 Executor/EntryProcessor | 分布式 SQL/机器学习集成 | 分布式流/任务 |
| 一致性 | 可配（线性一致选项） | ACID 事务（跨分区） | 可配（同步/异步复制） |
| 持久化 | 企业版功能 | 原生（写穿/写后） | 缓存存储 SPI |
| 生态位 | Java 企业级会话/缓存 | 金融级实时计算（风控/特征） | Red Hat 中间件栈 |

**甜点场景**（选型指纹 F22-f 的补充判定）：① 计算密集且数据局部性收益大（风控规则评估/实时特征拼接）；② 已有 JVM 技术栈；③ 需要跨节点事务。纯缓存需求勿选（复杂度价格：集群发现/序列化/类版本管理三重运维面）。

## 4.6 Valkey 9.x I/O 线程机制深描（2026-11-18 核验）

> 出处：[Valkey 官方博客 9.1（2026-05）](https://valkey.io/blog/valkey-9-1-delivers-improvements-in-security-performance-and-more/)、[andrewbaker 架构指南（2026-10）](https://andrewbaker.ninja/2026/01/04/redis-vs-valkey-enterprise-architecture-guide/)（C 级交叉核验）

**I/O 线程通信模型重构（9.1 核心）**：

| 项 | 旧设计（8.x 及以前） | 新设计（9.1） |
| -- | ------------------- | ------------- |
| 任务分发 | 主线程轮询 pending clients 列表，**预先分配**给特定线程 | **共享无锁队列**，空闲线程自行拉取 |
| 完成响应 | 主线程轮询各线程状态 | **响应队列**，主线程检查而非轮询 |
| 线程伸缩 | 固定配置 | **队列深度 + 主线程 CPU** 驱动 |

- 基准（官方）：**2.1M RPS**（512B 负载、9 I/O 线程、pipeline 10）；通信重构贡献 +17%；GET/流操作 +30%。
- 第三方交叉：Percona 2025 实测 Valkey 8.0 1.2M RPS；AWS 报告吞吐 +270%/延迟 -70%（8.x 线）；五组独立基准方向一致（[tech-insider 2026-10](https://tech-insider.org/valkey-vs-redis-2026/)）。
- 观测性：9.1 新增主线程/I/O 线程**使用率指标**（busy-loop 使 CPU% 虚高的老问题解决）。
- 9.0 独有功能（Redis 无对应）：**HEXPIRE/HPERSIST**（哈希字段级 TTL，"项目史上最高频请求"）、原子槽迁移；9.1 加数据库级 ACL（多租户）+ 内存 -10%。

## 4.7 Garnet 架构深描（VLDB 2026 论文精读）

> 出处：Chandramouli et al., PVLDB 19(2):224-237（论文原文精读，2026-11-18）

**四大设计支柱**：

1. **Tsavorite 存储引擎**：双存储分离（string store 内联字节 + object store 堆对象指针）；**RUMDS 五操作窄接口**（Read/Upsert/Modify/Delete/Scan）——250+ RESP 命令全部映射到这五个原语的回调；latch-free 哈希索引（64B cache-line 桶）+ 记录日志（内存环形页 + 磁盘追加 48 位逻辑地址）；**revivification**（过期/删除槽位回收复用，缓解日志结构空间放大）。
2. **EPSM（epoch-protected state machine）**：所有控制面操作（哈希扩容、快照、页刷出、槽迁移）的统一非阻塞框架——**后台任务驱动**（应用线程不参与控制面动作，避免延迟毛刺，与 FASTER 的协作式 epoch 不同）。
3. **可调持久性**：非阻塞快照（CPR 扩展——跨双存储一致 + 事务版本 v/v+1 协调）；**DOL 确定性操作日志**（RUMDS 层而非 RESP 层，含时间戳/随机数等确定性字段；组提交；分层提交——SSD 100μs 确认+云 5ms 后台，重启全恢复/换机部分恢复）。
4. **网络/集群**：可插拔网络层（TCP/eRPC/**DPDK/RDMA 内核旁路**）；会话内批处理**零线程切换**；16384 槽集群（RESP 协议兼容）+ **服务器直连槽迁移**（Redis 靠客户端 MIGRATE 网络流量大，Garnet 服务器对服务器传输）+ DOL 流式复制。

**事务**：混合并发控制——悲观 2PL（桶级锁、排序防死锁）+ 乐观 WATCH（版本表）；MULTI/EXEC/Lua/存储过程统一支持。

**论文关键数据**：最高 100× 吞吐、4× 尾延迟降低（对照 RESP 同类）；**70%+ Redis 用户把 Redis 当数据库用**（论文引用调查）——印证"缓存-数据库边界模糊化"是 Garnet"可调持久性"设计的产品依据。

**贡献者经济学**：分层设计使社区贡献者无需理解 Tsavorite 即可加命令（已贡献 100+ 命令）——与 Redis 模块生态不同的演进路径。

## 4.8 内存安全维度（国际政策对齐，2026-11-18）

> 美国 ONCD《Back to the Building Blocks》(2024-02) 将内存安全列为国家安全要务；CISA/FBI《Product Security Bad Practices》(2024-10) 指出**用 C/C++ 新开发关键基础设施产品线显著提升国家安全风险**；CISA 要求关键软件厂商 2026-01-01 前发布内存安全路线图（来源：[CISA/ONCD 官方](https://www.whitehouse.gov/wp-content/uploads/2024/05/2024-Report-on-the-Cybersecurity-Posture-of-the-United-States.pdf)，A 级政策）。

| 项目 | 实现语言 | 内存安全 | 政策影响 |
| ---- | -------- | -------- | -------- |
| Redis / Valkey / Memcached / KeyDB / Dragonfly | C/C++ | ✗（传统漏洞类：CVE 历史中缓冲区溢出/UAF 占比高） | 新关键基础设施采购面临路线图压力 |
| Garnet | C#（托管） | ✓（GC + 类型安全） | **政策顺风**——VLDB 论文的隐藏卖点 |
| Dragonfly | C++ | ✗（宣称 sandboxing 缓解） | 同左 |
| Hazelcast/Ignite/Infinispan | Java | ✓（JVM 托管） | 政策顺风 |

**工程趋势**（C 级，交叉核验 2026-11）：Google 用 Gemini 代理将 C/C++ 依赖批量重写为 Rust（giflib 试点→全公司扩展）；Rust-for-Linux 使内核缓存组件可 Rust 化；**选型建议：政府采购/关基场景把内存安全列为硬性评分项，Garnet/JVM 系受益；C 系项目要求供应商出示内存安全路线图**。本项目 Redis 漏洞史（04.02）与此维度联动。

## 5. 前沿对齐（截至 2026-11）

- **治理归属成为选型第一维度**：Redis 许可变迁后，治理归属（LF/Apache/厂商）比性能对比更先被审查——与 [04.03.16 §2.1](../../04-架构设计/04.03-行业应用场景/04.03.16-云原生缓存趋势与实践.md) 云默认引擎结论一致。
- Garnet 以 VLDB 2026 论文确立学术地位；Valkey 9.x I/O 线程重构为 BSD 路线性能标杆。
- 数据网格类（Ignite/Hazelcast）在"缓存+计算融合"场景（金融风控/实时特征）保持生态位，通用缓存选型不优先（复杂度价格）。
