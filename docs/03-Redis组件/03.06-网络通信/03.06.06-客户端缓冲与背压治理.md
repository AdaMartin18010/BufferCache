# 03.06.06 客户端缓冲与背压治理

> 主库为每个客户端维护输出缓冲（output buffer），慢消费者会把缓冲撑满→连接被强杀→全量重连→复制风暴。这是生产中最常见的"自我放大故障"之一。本文论证三类客户端缓冲的机理、背压缺失的 pub/sub 风险、以及 client-output-buffer-limit 的配置模型。

## 1. 输出缓冲的三类用途与独立限额

Redis 为每个连接维护输出队列（server.h client 结构），按用途分三类独立限额（`client-output-buffer-limit`，官方配置文档，B 级）：

| 类别 | 用途 | 默认限额（8.x） | 超限行为 |
| ---- | ---- | ---------------- | -------- |
| normal | 普通客户端响应 | 0（不限制） | —— |
| replica | 副本同步输出 | 256MB / 64MB soft×60s | 断开副本连接（硬限立即/软限超时） |
| pubsub | 发布订阅推送 | 32MB / 8MB soft×60s | 断开订阅者 |

**硬限 vs 软限**：硬限（第一个数）立即断连；软限（第二个数×秒数）缓冲持续超限才断——软限容忍突发，硬限防内存失控（官方语义）。

## 2. 慢消费死亡循环的机制

典型的自我放大故障链（机制推导自复制流程，B 级）：

```text
从库消费慢（CPU/网络/大 key 回放）→ replica 输出缓冲增长
  → 超 soft/hard 限额 → 主库断开从库
    → 从库重连 → 走 PSYNC 部分重同步（若 backlog 足够）
      → backlog 不足（慢消费期间 backlog 被覆盖）→ 全量重同步（RDB 传输）
        → 全量传输期间主库 fork + 网络放大 → 业务延迟尖峰
          → 业务更慢 → 从库消费更慢 → 循环
```

**断裂点**（任一即可）：
- 软限时限拉长 + backlog 容量按"断链窗口×写入速率"配置（[07.05.02 复制链路](../../07-运维与部署/07.05-集群管理/07.05.02-集群运维实践.md)）。
- 从库消费速率监控（`master_last_io_seconds_ago` + 缓冲水位代理指标：从库 `mem_client_normal`）。

## 3. Pub/Sub 的无缓冲风险

Pub/Sub 的语义是**fire-and-forget**（Redis pub/sub 文档，B 级）：推送写入订阅者输出缓冲，缓冲由 `pubsub` 类限额约束——**但不保证送达**（订阅者断开即丢）。风险矩阵：

| 场景 | 风险 | 缓解 |
| ---- | ---- | ---- |
| 突发大消息 × 慢订阅者 | pubsub 缓冲膨胀→断订→消息丢失 | 限额收紧 + 订阅者消费监控 |
| 关键事件（订单变更） | 消息丢失无感知 | 改 Redis Streams（持久 + 消费组滞后追踪，[03.01.08](../03.01-核心数据结构/03.01.08-Stream流数据结构.md)） |
| 大量订阅者同时断开重连 | resubscribe 风暴打主库 | 订阅逻辑客户端缓存 + 退避 |

**选型判据**：允许丢失的广播（缓存失效通知）→ pub/sub；不允许丢失的事件流 → Streams（[04.04.08 §4](../../04-架构设计/04.04-缓存问题与治理/04.04.08-缓存失效传播与一致性链路.md) 级联失效广播的选型依据）。

## 4. 配置模型与观测

```conf
# 配置范式（按实例角色分层，C 级经验起点）
client-output-buffer-limit replica 512mb 128mb 120   # 大实例同步容忍
client-output-buffer-limit pubsub 64mb 16mb 60       # 订阅者保护
# normal 默认不限制：除非有已知慢客户端（MONITOR/KEYS 扫描场景）
```

**观测指标**：`client_recent_max_output_buffer`（最近最大缓冲）、`mem_clients`（客户端内存总量）、`rejected_connections`、从库断连事件日志。大 key 传输（GET bigkey）瞬时撑缓冲属正常突发，看趋势不看单点。

## 5. 场景

1. **大 key 误操作**：`KEYS *` 或 `HGETALL` 大 hash 打满缓冲 → 客户端被断 → 重试风暴。限流 + 命令审计（[04.04.05 大 Key](../../04-架构设计/04.04-缓存问题与治理/04.04.05-大Key问题.md) 联动）。
2. **跨机房从库**：RTT 高 + 带宽窄 → replica 缓冲常满 → 全量重同步循环；专线限速 + 断链窗口内告警。
3. **监控告警接入**：`mem_clients > maxmemory × 5%` 告警（缓冲失控先行指标）。
