# 04.02.02 机密计算中的缓存设计

> [04.02](../04.02-缓存安全/README.md) 覆盖了对缓存的攻击（CacheWarp/侧信道）；本文反向论证：**在 TEE（可信执行环境）内部设计缓存系统的特殊约束与方案**——机密计算普及（TDX/SEV-SNP/Azure Confidential VM 2026 标配化）后的设计前沿。

## 1. TEE 内缓存的三重约束

| 约束 | 机制 | 缓存设计含义 |
| ---- | ---- | ------------ |
| **EPC 容量墙** | SGX enclave 内存加密页有限（128MB-1TB 级，平台相关）；TDX/SEV-SNP 是 VM 级（GB-数 TB） | SGX 场景：缓存必须**显式管理驻留集**（超出 EPC 换页开销 ~μs 级，比 DRAM miss 贵 100×）；TDX 场景约束宽松 |
| 密文内存的缓存侧信道 | 加密内存的访问模式仍泄露（地址总线可见） | 敏感数据的缓存访问需 **oblivious 访问模式**（固定顺序扫描/填充）——高吞吐缓存（哈希表随机探测）与 oblivious 天然冲突 |
| 不可信外部缓存**失效** | OS/管理程序控制的 OS 页缓存不可信（CacheWarp 类攻击） | TEE 内缓存不依赖外部页缓存语义；持久化用 TEE 内的日志（如 SEV 的 RMP 保护） |

## 2. 设计模式

| 模式 | 机制 | 适用 |
| ---- | ---- | ---- |
| TEE 内托管缓存 | Redis/Garnet 跑在 TEE VM（TDX/SEV-SNP）内 | 通用——可信根到 VM 边界，缓存语义不变 |
| Enclave 感知缓存 | SGX 内缓存层+外部大容量加密缓存（应用层加密后外包） | EPC 受限场景；加密密钥在 enclave 内 |
| Oblivious 缓存 | ORAM 式访问模式混淆 | 最高威胁模型（同机敌手）；吞吐代价 10-100×（研究前沿，C 级） |
| 缓存侧信道加固 | 固定时间访问、缓存行填充、分区（CAT） | 密码学操作在 TEE 内的缓存使用（04.02 防护体系的 TEE 内化） |

## 3. 成熟度与选型（2026-11）

- **TEE VM 内跑缓存**：成熟（TDX/SEV-SNP VM 即普通 VM+加密）；代价是加密内存吞吐 ~5-15% 损失（SEV 实测口径）+ 开机证明（attestation）集成。
- **SGX enclave 细粒度缓存**：研究/专用场景（MesaTEE 类）；工程复杂度高。
- **建议**：金融/政务密态计算需求 → TEE VM 内 Redis/Valkey（含 [TC-CLUS 系列](../../../../Testing/cases/04-集群/) 演练+ attestation 集成）；极端敌手模型 → oblivious 路线评估（学术跟踪）。
