## 1. CDN 三级缓存架构

```text
Edge PoP（330+ 节点，毫秒级）      ← 静态资产/可缓存 API 的首站
   ↓ miss
Regional Tier / Origin Shield（区域汇聚层）  ← 回源汇聚，防止 thundering herd 打到源站
   ↓ miss
Origin（源站：对象存储 / 应用服务器）        ← 最终权威
```

- **Origin Shield 是架构关键**：无 shield 时每个 PoP 独立回源，N 个 PoP × miss = N 倍源站压力；shield 层把回源收敛为每区域一次（Cloudflare Cache Reserve 直接用 R2 对象存储做 shield 层，源站零请求）。
- **边缘计算把 CDN 从"缓存层"升级为"运行时"**：2026 年 CDN 已是全栈边缘平台（加速+DDoS+零信任+边缘函数+KV 存储），不再只是静态资产分发（[serverpicks 2026-06](https://www.serverpicks.net/blog/cdn-edge-computing-showdown-2026-akamai-cloudfront-fastly-cloudflare)，C 级行业综述）。

| 平台 | PoP/覆盖 | 边缘运行时 | 边缘 KV/状态 | 缓存清除 | 带宽价（北美，2026 初） | 出处 |

## 3. 缓存键设计与失效

- **键 = URL + 可缓存响应属性**：`Vary` 头、Cookie 白名单、查询串白名单；现代平台支持自定义键表达式（Cloudflare Custom Cache Key、CloudFront 键含标头/ cookie）。
- **失效三手段**：TTL（秒-天级）、显式清除（单 URL/标签/全站；Fastly 亚秒级全球最快）、版本化 URL（`?v=hash` 免清除——配合 04.44.08 版本号思路）。
- **投毒防线**（[04.02 缓存安全](../04.02-缓存安全/README.md)）：未键化头不入键、错误响应不缓存、`Host` 校验——CDN 层 CPDoS 防护见该篇。

## 4. CDN 与应用缓存的边界决策

```text
内容是什么？
├─ 静态资产（图片/JS/CSS/视频）→ CDN 直出（+ 版本化 URL），应用零缓存代码
├─ 可匿名缓存的 API 响应（公开目录/文章）→ CDN 边缘缓存 + TTL/清除
├─ 个性化但可键化的响应（A/B、地区）→ CDN + 自定义键（Vary/白名单）
├─ 需要程序逻辑判定的缓存（权限/复杂依赖）→ 应用层缓存（Redis/PG内嵌），CDN 仅静态
└─ 会话/写路径 → 不缓存（CDN 只过流量），应用层负责
```

**与应用缓存（Redis/PG 内嵌）的关系**：CDN 是**只读共享的前置层**——命中即零应用负载；应用缓存管个性化/动态部分；两者用 TTL/清除联动（应用写后调 CDN 清除 API）。层级账：edge 命中 ~10ms → 应用缓存命中 ~1-5ms（内网）→ DB（ms 级）——逐层放大保护。

## 4.5 CDN 边缘安全与防护联动（2026-11-18 补）

CDN 是攻击面的第一接触点，边缘安全规则与 [04.02 缓存安全](../04.02-缓存安全/README.md) 的分工：

| 层 | 防护项 | 机制 | 出处 |
| -- | ------ | ---- | ---- |
| 边缘 WAF | OWASP Top10/自定义规则 | Cloudflare WAF/Fastly Next-Gen WAF（机器学习方法） | 厂商文档 |
| 缓存投毒防线 | 未键化头隔离 | Host 校验、错误响应不缓存、`Vary` 最小化 | [04.02 CPDoS 节](../04.02-缓存安全/README.md) |
| 边缘鉴权 | 签名 URL/Cookie（HMAC） | 付费内容/私有分发的访问控制 | 厂商文档 |
| Bot 缓解 | 边缘 JS 挑战/速率限制 | 缓存键无关的流量清洗 | 厂商文档 |
| 零信任接入 | 私有源站（源站只允许 CDN IP 段） | 防火墙白名单+mTLS 回源 | 厂商文档 |

**源站隐藏是 CDN 安全的第一原则**：源站 IP 一旦泄露，攻击者绕过 CDN 直打源站——防火墙白名单+mTLS 回源是标配（与 04.02 的纵深防御一致）。

## 5. 成本结构与隐藏成本

每 GB 标价为冰山一角，隐藏成本六项（[cdncost 2026-06](https://cdncost.com/hidden-cdn-costs)，C 级独立调研）：**per-request 费**（CloudFront $0.012/万次）、**源站出口费**（CDN 回源读源存储的出口）、**边缘计算 CPU 时间**（Workers/Fastly 按 CPU ms）、**清除操作费**（部分厂商）、**日志/分析出口**、**最低消费承诺**。选型时必须把"命中率 × 请求数 × CPU 时间"三元组代入总账（与 [04.05 成本优化](../04.05-成本优化/) 联动）。

## 6. 判定指纹与参考

| 指纹 | 结论 | 锚点 |
| ---- | ---- | ---- |
| F20-a | 静态资产+全球用户 → 缓存层 | CDN 直出（版本化 URL） | §4 第一支 |
| F20-b | 边缘需程序逻辑+低延迟 → 运行时 | Cloudflare Workers（生态最全）；Wasm 强隔离需求 → Fastly Compute | §2 表 |
| F20-c | 亚秒级全球清除是硬需求 → 厂商 | Fastly（业界最快） | §2 表 |
| F20-d | 预算敏感+基础分发 → 厂商 | Bunny/Cloudflare Pro（套餐内带宽免费） | §2/§5 |

**前沿对齐（截至 2026-11）**：CDN=边缘平台化是 2026 最大趋势；Workers KV/Durable Objects 把"边缘有状态"从不可能变为产品；CloudFront Functions+KVStore 缩小与 Cloudflare 差距；开源 Varnish/ATS 在自建与混合云仍有位置。
