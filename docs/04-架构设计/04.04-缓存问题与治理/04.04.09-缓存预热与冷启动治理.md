## 1. 概述：冷启动的代价结构

冷缓存期（预热完成前）的请求路径：

$$H_{cold} \approx 0 \Rightarrow \text{miss} \Rightarrow \text{回源 DB} \Rightarrow \text{回填}$$

代价三要素：
1. **DB 回源压力**：全部流量打到 DB，QPS 峰值 = 业务流量（对 DB 的"突袭"）。
2. **用户可见延迟**：miss 路径延迟 ≈ 命中路径 + 回源延迟（[05.04 数据流](../../05-全栈分析/05.04-数据流分析/) 的账）。
3. **级联风险**：DB 被打慢 → 回填更慢 → 预热更慢——负反馈循环（雪崩的启动形态，[04.04.02 缓存雪崩](04.04.02-缓存雪崩.md)）。

## 2. 预热数据源与策略

| 数据源 | 机制 | 精度 | 成本 |
| ------ | ---- | ---- | ---- |
| 历史访问日志重放 | 按时间序重放前 N 天 key 序列 | 高（真实热度） | 日志管道成本 |
| Heat Map 快照 | 上一轮运行的访问频次表（Aurora 预热思路，[02.03.06](../../02-系统实现/02.03-数据库缓存/02.03.06-云数据库缓存架构.md)） | 中高 | 需持续维护热度表 |
| 静态名单 | 人工/运营配置的 key 清单 | 低 | 几乎为零 |
| 懒加载 + 请求合并 | 不预热，靠 singleflight 扛（[04.04.03](04.04.03-缓存击穿.md)） | —— | 零预热成本，接受短期 miss |

**策略选型**：关键业务（支付前置库存）→ 日志重放或 Heat Map；一般业务 → 懒加载+合并 + 短 TTL 自愈；大促场景 → 主动预热（下一节）。

### 大促预热的时序设计

```text
T-24h: 流量预测 → 确定预热 key 集（Top N by 历史热度，N 按新容量 70% 水位折算）
T-12h: 第一波预热（离线管道灌入，限速避免打源库）
T-2h:  缺口检查（预热覆盖度 <90% 则补灌）
T-0:   流量切换；miss 路径全量带 singleflight
T+2h:  预热完成判据达成（见 §3）
```

## 3. 预热完成判据

预热不是"灌完数据"，而是"命中率恢复到可服务水位"。可测判据（C 级经验起点，项目可调）：

| 判据 | 目标 | 说明 |
| ---- | ---- | ---- |
| 命中率 | ≥ 基线命中率的 90% | 基线 = 稳定期同时间段命中率 |
| 回源 QPS | ≤ DB 安全水位的 30% | 安全水位见 [05.06.07](../../05-全栈分析/05.06-系统动态特征/05.06.07-基于指标的系统边界动态估算.md) 边界模型 |
| 热点覆盖 | Top 1000 key 的命中率 ≥ 99% | 热点 miss 的用户影响最大 |
| P99 延迟 | ≤ SLO | 用户侧最终判据 |

**量化关系**：预热完成后预期命中率恢复时间 ≈ 平均重用间隔 × ln(目标/当前)（推导自指数衰减逼近模型，C 级）——重用间隔 5min、目标 90% → ~11 个间隔 ≈ 55min 纯懒加载；主动预热把这个时间压缩到判据达成时刻。

## 4. 冷启动 miss 风暴模型

无防护冷启动瞬间，回源并发 = 全量业务 QPS（Q）。DB 作为回源服务，其吞吐边界 $\mu_{DB}$ 有限：

$$\lambda_{source} = Q(1 - h(t)), \quad h(t)\text{ 为 t 时刻命中率}$$

无 singleflight 时 h(t) 增长受 DB 服务能力限制（回填率 ≤ μ_DB 的占比），可能长期停留在低水位（负反馈）。防护的数学作用：

| 防护 | 模型效果 |
| ---- | -------- |
| singleflight | 回源并发从 Q 降为 1（每 key），DB 压力 = 唯一 key 数 / 时间窗 |
| 逻辑过期（返回旧值） | 用户侧无感，h(t) 的"有效分母"不含并发重复（[04.04.08](04.04.08-缓存失效传播与一致性链路.md) §3 同源） |
| 随机回源抖动 | 摊平 λ 的尖峰（[04.04.08](04.04.08-缓存失效传播与一致性链路.md) §4） |

## 5. 灰度与影子流量预热

新集群/新版本上线时的安全预热：

1. **灰度流量切入**：1% → 10% → 50% → 100%，每档观察命中率与回源水位（[07.02 CI/CD](../../07-运维与部署/07.02-CI-CD实践/) 的灰度门禁复用）。
2. **影子流量双读**：新集群以影子模式并行接收读请求（不返回结果），自然填充缓存——零风险预热，代价是影子期间的资源开销。
3. **回源写穿透预热**：新集群 miss 时不只回填自己，还异步通知旧集群——并行过渡期两集群命中率都保护（双写窗口的一致性见 [04.04.08](04.04.08-缓存失效传播与一致性链路.md) §4）。

## 6. 场景

1. **每日重启的容器化缓存**（成本低但冷启动频繁）：Heat Map 持久化到卷 + 启动重放（秒级预热）。
2. **大促前容量翻倍**：§2 时序设计 + 07.09.04 分片扩容。
3. **跨机房灾备切换**：备用机房平时以影子流量保持热度（温备），切换时命中率 ≥80%。
