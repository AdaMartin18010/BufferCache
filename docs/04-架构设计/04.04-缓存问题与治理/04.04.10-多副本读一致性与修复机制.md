## 1. 概述：异步复制的根本约束

Redis 主从复制是异步的：主库写返回 **先于** 复制传播完成（`WAIT` 命令除外）。由此产生的根本约束：

$$T_{write\_visible} = T_{write} + T_{replica\_lag}$$

从库在滞后窗口内可能返回旧值。**不存在"写后立刻从任意副本读到"的免费保证**——要么接受滞后（最终一致），要么付出同步代价（WAIT 降低可用性，与 [08.03.01 Redlock 争议](../../08-分布式架构/08.03-分布式协调/08.03.01-分布式锁实践.md) 同源）。

## 2. 副本滞后度量

| 指标 | 获取 | 用途 |
| ---- | ---- | ---- |
| `master_repl_offset - slave_repl_offset` | INFO replication | 滞后字节数（回放时间 ≈ 滞后字节 / 应用速率） |
| `master_last_io_seconds_ago` | INFO replication | 复制连接活性（>10s 告警） |
| `slave_repl_offset` 增速 vs 主库 | 周期采样 | 追赶/发散趋势 |
| 复制积压缓冲区占用率 | `repl_backlog_histlen / repl_backlog_size` | 断线重连是否走全量 |

**滞后时间的换算**（推导自复制流水线，B 级）：$T_{lag} \approx \Delta_{offset} / R_{apply}$，$R_{apply}$ 为从库应用速率（正常 ≈ 主库写入速率，压测可得）。

## 3. 读一致性级别

按读操作的滞后容忍分级路由（项目设计模式，B 级结构 + C 级参数）：

| 级别 | 语义 | 路由策略 | 代价 |
| ---- | ---- | -------- | ---- |
| 任意读 | 可能旧值 | 随机/就近副本 | 读扩展性最好 |
| 有界旧读 | 滞后 ≤ 预算 τ | 滞后 ≤ τ 的副本；超预算读主 | 需滞后度量（§2） |
| 主读（读写同点） | 新写后读主 | 写后 N ms 内的读路由到主 | 主库读压力 +N ms 窗口 |
| 会话一致（sticky） | 同一客户端单调读 | 客户端绑定副本（故障转移时重新协商） | 负载不均风险 |
| WAIT 强一致 | 等副本确认 | `WAIT 1 100`（≥1 副本在 100ms 内） | 写延迟 ↑，副本故障时超时降级 |

**级别组合**是常态：读多写少的会话缓存 = 任意读 + 会话一致；库存/余额 = 主读或 WAIT。

## 4. 读修复与 hinted handoff

### 4.1 读修复（read repair）

客户端/代理检测到旧值（版本号或时间戳比对）→ 主动回写新值到滞后副本：

- 触发条件：读路径比对发现版本落后（L3 版本号链路天然支持，[04.04.08](04.04.08-缓存失效传播与一致性链路.md) §2.3）。
- 成本：每次修复一次额外写；适合**读频繁且副本少**的场景。
- 与 Cassandra 读修复的区别：缓存副本是完整副本（非分片多副本），修复即单 key 覆盖，无 Merkle 树需求。

### 4.2 Hinted handoff（写接力）

副本短暂不可用（重启/网络抖动）时，主库把该副本的写暂存 hint 队列，副本恢复后补放：

- Redis 无原生支持；实现路径：客户端双写缓冲 / 代理层队列 / 应用层 outbox。
- 与 AOF 的关系：主库 AOF 本身就是完整写日志——**极端简化版 handoff = 从库重放主库 AOF 片段**（按 offset 区间），与 PSYNC2 部分重同步共用机制。

## 5. 滞后预算路由

"有界旧读"的工程实现（设计模式，B 级）：

```text
读请求进入 → 一致性级别声明（默认有界旧读，τ=200ms）
  → 查副本滞后表（周期刷新的 per-slave T_lag）
  → T_lag ≤ τ ? 路由该副本 : 路由主库
  → 采样验证：周期性把同一 key 双读（副本+主）比对，校准 τ 的有效性
```

τ 的选取 = 业务可容忍旧值时长（产品决策）与 读扩展收益 的权衡。τ=0 退化为全主读；τ=∞ 退化为任意读。**校准闭环**：双读采样的不一致率 >1% → τ 收紧或副本健康检查。

## 6. 场景

1. **读多写少商品详情**：任意读 + 每日全量对账（低峰比对主从 key 抽样哈希）。
2. **会话缓存**：sticky 到副本；副本故障时客户端重连主库并重建会话（TTL 兜底）。
3. **库存扣减**：主读 + WAIT 1 100 双保险；或与 DB 层乐观锁联动（缓存永不作为库存真相源）。
4. **跨机房复制**（灾备温备）：滞后预算放宽到秒级 + 读修复，灾备机房平时承载只读流量。
