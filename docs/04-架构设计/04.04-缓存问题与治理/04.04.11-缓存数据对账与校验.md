# 04.04.11 缓存数据对账与校验

> 缓存与数据源长期运行后必然存在静默漂移（删缓存失败、并发窗口、代码 bug 的积累）。对账（reconciliation）是发现漂移的最终手段。本文论证对账的机制设计、抽样统计、主从一致性校验，以及可执行的最小工具。

## 1. 概述：漂移的来源与对账目标

漂移来源（机制层，B 级）：删除失败（[04.04.08](04.04.08-缓存失效传播与一致性链路.md) L1 链路的固有窗口）、并发写覆盖（Last-Write-Wins 的意外胜者）、双写不一致（DB 事务回滚但缓存已删/已写）、key 命名空间冲突。

对账的**两个目标**：

1. **发现漂移**：量化不一致率（不应是 0；0 反而说明对账本身有盲区）。
2. **修复漂移**：自动刷新（删除+回源重建）或人工审计（超阈值时）。

## 2. 对账机制设计

| 维度 | 方案 | 适用 |
| ---- | ---- | ---- |
| 全量对账 | DB 全表扫描 × 缓存逐 key 比对 | 小数据量（<千万）、夜间窗口 |
| 抽样对账 | 随机 N key 比对 | 大数据量的常态巡检（本项目推荐起点） |
| 影子比对 | 读请求双读 DB+缓存比对（异步采样 1%） | 准实时、零窗口侵入 |
| 校验和比对 | 分桶 CRC/哈希值比对（不逐 key） | 快速粗检（不一致再下钻） |

**版本化 value 是廉价对账锚点**：value 内嵌 `version + updated_at`（[04.04.08 §2.3](04.04.08-缓存失效传播与一致性链路.md) 的 L3 链路天然支持），对账只需比对版本而非业务字段。

## 3. 抽样统计与误差判据

抽样 N 个 key，发现 k 个不一致，不一致率估计 $\hat{p} = k/N$，95% 置信区间（Wald 近似，B 级）：

$$\hat{p} \pm 1.96\sqrt{\frac{\hat{p}(1-\hat{p})}{N}}$$

| 采样 N | 检出 0.1% 级漂移所需 | 置信区间半宽（p=0.1%） |
| ------ | -------------------- | ---------------------- |
| 1,000 | 期望发现 1 个 | ±0.62%（太粗） |
| 10,000 | 期望 10 个 | ±0.20% |
| 100,000 | 期望 100 个 | ±0.06% |

**判据设计**（项目经验，C 级）：不一致率 >0.1% 触发自动刷新；>1% 触发告警+根因调查；>5% 判定为系统性故障（非漂移）走应急预案。

## 4. 主从一致性校验

主从复制是逐命令回放，理论上终态一致；实际漂移场景：

| 场景 | 机制 | 校验方法 |
| ---- | ---- | -------- |
| 主从断链窗口双写 | 异步复制的固有滞后（[04.04.10](04.04.10-多副本读一致性与修复机制.md)） | 滞后预算内不对账，超预算比对 |
| 全量重同步中断 | RDB 传输中断后残留半态 | resync 完成后自动全量覆盖（机制保证，校验点：重同步完成事件后抽检） |
| 主从 expire 处理差异 | 惰性过期由各自时钟触发 | 周期性 `DEBUG JMAP`？——不，用 `SCAN + STTL` 抽检过期 key 双端状态 |

**校验和工具**：`redis-cli --cluster check` 查槽覆盖；逐实例 `DBSIZE` + 抽样 `DUMP` 值哈希比对（DUMP 输出含序列化字节，哈希即可）。

## 5. 最小可执行工具

项目已具备的对账资产（无需新工具链）：

```bash
# 1. 主从滞后对账（运维例行）
redis-cli INFO replication | grep -E "master_repl_offset|slave_repl_offset"

# 2. 抽样值比对（从库 vs 主库，shadow 抽检）
redis-cli --rdb /tmp/dump.rdb   # 全量序列化，离线分析（大实例谨慎）

# 3. 缓存-DB 漂移抽检（应用层采样双读，05.06 延迟指标联动）
#    由客户端埋点实现，Testing 用例：TC-BENCH-003 的一致性窗口实验即漂移成因验证
```

新增自动化建议（批次后续）：`scripts/reconcile_sample.py`——按命中率最低的 1000 key 名单（来自监控）自动双读比对并输出漂移报告（输入：key 名单；输出：不一致列表+率）。

## 6. 场景

1. **夜间巡检**：抽样 10 万 key 对账 + 漂移自动删除重建，报告进 STATUS 式归档。
2. **发布前后**：新版本灰度期 shadow 比对率提高到 5%（快速暴露写路径 bug）。
3. **跨机房切换后**：主从角色互换后首轮全量校验（角色切换是漂移高发点）。
