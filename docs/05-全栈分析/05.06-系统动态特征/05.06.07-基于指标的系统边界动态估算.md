## 1. 概述：边界的三种形态

| 边界 | 定义 | 典型指标 |
| ---- | ---- | -------- |
| 吞吐边界 | 再加快到达率则延迟发散 | 利用率 ρ→1（M/M/1） |
| 内存边界 | 驱逐率 > 命中率收益平衡点 | maxmemory 水位 + 驱逐 QPS |
| 稳定性边界 | 毛刺/重试/降级开始自我放大 | 错误率、重试率拐点 |

边界估算的价值：在**未到达边界时**知道距离，给扩容决策提供提前量（[07.09.04](../../07-运维与部署/07.09-弹性伸缩与自愈/07.09.04-分片级弹性伸缩与分区迁移.md) 主动伸缩的输入）。

## 2. 排队论边界模型

### 2.1 M/M/1 基线（Kleinrock，B 级）

单线程 Redis 近似为单服务台队列（严格说请求处理是确定时长，M/D/1 更贴切；M/M/1 给出保守上界）：

$$\rho = \frac{\lambda}{\mu}, \quad E[W] = \frac{\rho}{\mu(1-\rho)} = \frac{1}{\mu - \lambda}$$

- $\lambda$：请求到达率（redis 的 instantaneous_ops_per_sec）
- $\mu$：服务率（[07.05.04 实测基线](../../07-运维与部署/07.05-集群管理/07.05.04-集群容量规划.md)：SET ~65K QPS、GET ~256K QPS，混合作业按读写比加权）

**边界读出**：给定当前 λ 与测得平均延迟 W，反解 $\mu = \lambda + 1/W$，再算当前利用率 $\rho$ 与"距离边界" $1-\rho$。例：λ=30K、W=0.2ms → μ≈35K、ρ≈0.86——距离吞吐边界仅 14% 的余量。

### 2.2 多资源边界取小

系统边界 = min(CPU 边界, 内存边界, 网络边界, 磁盘边界)。任一资源先到 ρ→1 即整体边界。**度量要点**：同时采集 CPU（sys+user）、内存水位、网卡吞吐、磁盘 util，取最陡上升者作为边界资源（USE 方法，Brendan Gregg《Systems Performance》，B 级）。

### 2.3 利用率法则（Universal Scalability Law 简化）

Amdahl  + 协作开销的边界预测（Gunther《Guerrilla Capacity Planning》，B 级）：

$$X(N) = \frac{N}{1 + \alpha(N-1) + \beta N(N-1)}$$

- $\alpha$：串行化 fraction（Amdahl），$\beta$：一致性/协作开销系数
- 拟合 3 个压力点即可外推拐点 N*（β>0 时 X 先升后降——**协作开销导致越过某并发后吞吐回退**，即"边界"）

## 3. 拐点探测协议

不在生产直接压到拐点，用**阶梯加压 + 早期信号**外推：

```text
1. 基线测量：3 个并发阶梯（如 1×/2×/4× 当前流量），各 10min
2. 每阶梯记录：吞吐量 X、平均延迟 W、P99、错误率
3. 拟合 X(N)（USL 或线性外推）+ 观察 P99/W 的斜率变化
4. 拐点判据：dW/dN 连续两阶梯翻倍（延迟二阶导>0）→ 距拐点 ≤1 个阶梯
5. 输出：当前利用率、外推拐点、建议余量阈值（拐点/1.3 为告警线）
```

精度声明：外推误差随非线性增强而增大，过拐点 1.5× 后不可外推（必须实测）；以 [TC-BENCH](../../../Testing/cases/02-形式化与基准/) 系列和 redis-benchmark 提供阶梯数据。

## 4. 饱和度先行指标

边界到达前 5-15 分钟出现的信号（经验集，C 级，项目可实测校准）：

| 先行指标 | 机制 | 观测窗口 |
| -------- | ---- | -------- |
| 上下文切换率陡增 | 单线程事件循环被多任务挤压 | 5min 斜率 |
| 网卡 interrupt coalescing 后 P99 分层 | 批处理延迟引入尾延迟 | 实时 |
| 内存碎片率突升 | 驱逐压力增大前兆 | 15min |
| 慢查询数抬升（非业务变更） | 队列变长的滞后信号 | 10min |
| CPU iowait 占比 >2% | AOF/fsync 与请求竞争 | 5min |

**边界预警 = 先行指标组合判分**（单项噪点高，3/5 项同向时置信度高）。

## 5. 与容量工具的校准闭环

```
redis-benchmark 阶梯 → 拟合 μ/α/β → 边界模型
        ↓                              ↓
capacity_calculator 的 --qps-per-core ← 用实测 μ 覆盖默认值
        ↓                              ↓
   容量评审（正向设计） ←——→ 边界监控（反向校验）
```

- 每次 TC 用例实测（redis-lab）后更新 [事实断言清单](../../00-项目总览/事实断言清单.md) C 类参数
- 边界外推值与下一次实测偏差 >30% → 回校模型（美国谚语："所有模型都错，但有些有用"——Box）

## 6. 场景

1. **上线前容量确认**：阶梯压测外推拐点，确认生产流量 ≤ 拐点/1.3。
2. **扩容时机**：边界余量 <20% 且先行指标 3/5 触发 → 触发 07.09.04 L2 扩容审批。
3. **配置变更评估**：改 maxmemory/持久化参数后重测边界，对比变更前后（防性能回归）。
