## 1. 概述

告警规则与通知是Redis监控体系的重要组成部分，确保及时发现和处理系统异常。

**告警目标**：

- ✅ 及时发现系统异常
- ✅ 快速通知相关人员
- ✅ 避免告警风暴
- ✅ 提供可操作的告警信息

**告警范围**：

- 系统级告警（实例宕机、资源耗尽）
- 性能告警（延迟过高、QPS异常）
- 业务告警（命中率低、错误率高）
- 集群告警（节点故障、槽位异常）

## 2. 告警规则设计

### 2.1 告警规则分类

**告警严重程度分类**：

| 级别 | 描述 | 响应时间 | 通知方式 |
| ------ | ------ | --------- | --------- |
| **Critical** | 系统完全不可用 | <5分钟 | 电话+短信+邮件 |
| **Warning** | 性能下降或异常 | <15分钟 | 邮件+消息 |
| **Info** | 信息性告警 | <1小时 | 邮件 |

**告警类型分类**：

1. **可用性告警**：实例宕机、服务不可用
2. **性能告警**：延迟过高、QPS异常
3. **资源告警**：内存、CPU、网络使用率过高
4. **业务告警**：命中率低、错误率高
5. **集群告警**：节点故障、槽位异常

### 2.2 关键告警规则

**Prometheus告警规则文件**：

```yaml
# alerts.yml
groups:
  - name: redis_availability
    interval: 30s
    rules:
      # Redis实例宕机
      - alert: RedisDown
        expr: redis_up == 0
        for: 1m
        labels:
          severity: critical
          team: platform
          component: redis
        annotations:
          summary: "Redis instance {{ $labels.instance }} is down"
          description: |
            Redis instance {{ $labels.instance }} has been down for more than 1 minute.
            Cluster: {{ $labels.cluster }}
            Role: {{ $labels.role }}

      # Redis连接失败
      - alert: RedisConnectionFailed
        expr: redis_exporter_up == 0
        for: 2m
        labels:
          severity: warning
          team: platform
        annotations:
          summary: "Redis exporter connection failed"
          description: "Cannot connect to Redis instance {{ $labels.instance }}"

  - name: redis_performance
    interval: 30s
    rules:
      # QPS过高
      - alert: RedisHighQPS
        expr: |
          sum(rate(redis_commands_processed_total[5m])) by (instance) > 100000
        for: 5m
        labels:
          severity: warning
          team: platform
        annotations:
          summary: "High QPS on {{ $labels.instance }}"
          description: |
            Redis instance {{ $labels.instance }} has QPS of {{ $value }}.
            This is above the threshold of 100,000 QPS.

      # 延迟过高
      - alert: RedisHighLatency
        expr: |
          histogram_quantile(0.99, rate(redis_latency_seconds_bucket[5m])) > 0.01
        for: 5m
        labels:
          severity: warning
          team: platform
        annotations:
          summary: "High latency on {{ $labels.instance }}"
          description: |
            P99 latency on {{ $labels.instance }} is {{ $value }}s.
            This is above the threshold of 10ms.

      # 命中率过低
      - alert: RedisLowHitRate
        expr: |
          (
            sum(rate(redis_keyspace_hits_total[5m])) by (instance) /
            (sum(rate(redis_keyspace_hits_total[5m])) by (instance) +
             sum(rate(redis_keyspace_misses_total[5m])) by (instance))
          ) < 0.8
        for: 10m
        labels:
          severity: warning
          team: platform
        annotations:
          summary: "Low hit rate on {{ $labels.instance }}"
          description: |
            Cache hit rate on {{ $labels.instance }} is {{ $value | humanizePercentage }}.
            This is below the threshold of 80%.

  - name: redis_resources
    interval: 30s
    rules:
      # 内存使用率过高
      - alert: RedisHighMemoryUsage
        expr: |
          (redis_memory_used_bytes / redis_memory_max_bytes) > 0.9
        for: 5m
        labels:
          severity: warning
          team: platform
        annotations:
          summary: "High memory usage on {{ $labels.instance }}"
          description: |
            Memory usage on {{ $labels.instance }} is {{ $value | humanizePercentage }}.
            Used: {{ $value | humanize1024 }}GB
            Max: {{ $value | humanize1024 }}GB

      # 内存使用率临界
      - alert: RedisCriticalMemoryUsage
        expr: |
          (redis_memory_used_bytes / redis_memory_max_bytes) > 0.95
        for: 2m
        labels:
          severity: critical
          team: platform
        annotations:
          summary: "Critical memory usage on {{ $labels.instance }}"
          description: |
            Memory usage on {{ $labels.instance }} is {{ $value | humanizePercentage }}.
            Immediate action required!

      # 连接数过多
      - alert: RedisTooManyConnections
        expr: |
          redis_connected_clients > 10000
        for: 5m
        labels:
          severity: warning
          team: platform
        annotations:
          summary: "Too many connections on {{ $labels.instance }}"
          description: |
            Redis instance {{ $labels.instance }} has {{ $value }} connections.
            This is above the threshold of 10,000.

  - name: redis_cluster
    interval: 30s
    rules:
      # 集群槽位异常
      - alert: RedisClusterSlotIssue
        expr: |
          redis_cluster_slots_fail > 0
        for: 1m
        labels:
          severity: critical
          team: platform
        annotations:
          summary: "Redis cluster slot issue"
          description: |
            Redis cluster has {{ $value }} failed slots.
            Cluster: {{ $labels.cluster }}

      # 集群节点故障
      - alert: RedisClusterNodeDown
        expr: |
          count(redis_up == 0) by (cluster) > 0
        for: 2m
        labels:
          severity: critical
          team: platform
        annotations:
          summary: "Redis cluster node down"
          description: |
            {{ $value }} node(s) down in cluster {{ $labels.cluster }}.

      # 复制延迟过高
      - alert: RedisHighReplicationLag
        expr: |
          (redis_master_repl_offset - redis_replication_offset) > 1000000
        for: 5m
        labels:
          severity: warning
          team: platform
        annotations:
          summary: "High replication lag on {{ $labels.instance }}"
          description: |
            Replication lag on {{ $labels.instance }} is {{ $value }} bytes.
            This is above the threshold of 1MB.

  - name: redis_business
    interval: 30s
    rules:
      # 错误率过高
      - alert: RedisHighErrorRate
        expr: |
          sum(rate(redis_errors_total[5m])) by (instance) /
          sum(rate(redis_commands_processed_total[5m])) by (instance) > 0.01
        for: 5m
        labels:
          severity: warning
          team: platform
        annotations:
          summary: "High error rate on {{ $labels.instance }}"
          description: |
            Error rate on {{ $labels.instance }} is {{ $value | humanizePercentage }}.
            This is above the threshold of 1%.

      # 慢查询过多
      - alert: RedisTooManySlowQueries
        expr: |
          sum(rate(redis_slowlog_length[5m])) by (instance) > 100
        for: 5m
        labels:
          severity: warning
          team: platform
        annotations:
          summary: "Too many slow queries on {{ $labels.instance }}"
          description: |
            {{ $value }} slow queries per second on {{ $labels.instance }}.
            This is above the threshold of 100.
```

### 2.3 告警规则最佳实践

**告警规则设计原则**：

1. **避免告警风暴**：合理设置`for`持续时间
2. **避免重复告警**：使用告警抑制和分组
3. **提供可操作信息**：告警描述包含处理建议
4. **分级告警**：根据严重程度设置不同响应时间

**告警规则优化示例**：

```yaml
# 优化前：可能产生告警风暴
- alert: RedisHighMemoryUsage
  expr: redis_memory_used_bytes / redis_memory_max_bytes > 0.9
  for: 0s  # 立即告警

# 优化后：避免告警风暴
- alert: RedisHighMemoryUsage
  expr: redis_memory_used_bytes / redis_memory_max_bytes > 0.9
  for: 5m  # 持续5分钟才告警
  labels:
    severity: warning
  annotations:
    summary: "High memory usage"
    runbook_url: "https://wiki.example.com/redis-memory-alert"
```

### 3.1 Alertmanager部署

**Alertmanager Docker部署**：

```yaml
# docker-compose.yml
version: '3.8'
services:
  alertmanager:
    image: prom/alertmanager:v0.26.0
    container_name: alertmanager
    ports:
      - "9093:9093"
    volumes:
      - ./alertmanager.yml:/etc/alertmanager/alertmanager.yml
      - alertmanager-data:/alertmanager
    command:
      - '--config.file=/etc/alertmanager/alertmanager.yml'
      - '--storage.path=/alertmanager'
      - '--web.external-url=http://localhost:9093'
    networks:
      - monitoring
    restart: unless-stopped

volumes:
  alertmanager-data:

networks:
  monitoring:
    driver: bridge
```

### 3.2 Alertmanager配置

**Alertmanager配置文件**：

```yaml
# alertmanager.yml
global:
  resolve_timeout: 5m
  smtp_smarthost: 'smtp.example.com:587'
  smtp_from: 'alertmanager@example.com'
  smtp_auth_username: 'alertmanager@example.com'
  smtp_auth_password: 'password'

# 告警路由
route:
  receiver: 'default-receiver'
  group_by: ['alertname', 'cluster', 'severity']
  group_wait: 10s
  group_interval: 10s
  repeat_interval: 12h

  routes:
    # Critical告警路由
    - match:
        severity: critical
      receiver: 'critical-receiver'
      group_wait: 5s
      group_interval: 5s
      repeat_interval: 1h
      continue: true

    # Warning告警路由
    - match:
        severity: warning
      receiver: 'warning-receiver'
      group_wait: 30s
      group_interval: 5m
      repeat_interval: 6h

    # 按团队路由
    - match:
        team: platform
      receiver: 'platform-receiver'

    # 按集群路由
    - match_re:
        cluster: '.*-prod-.*'
      receiver: 'production-receiver'

# 告警抑制规则
inhibit_rules:
  # 如果RedisDown告警，抑制其他Redis相关告警
  - source_match:
      alertname: 'RedisDown'
    target_match:
      alertname: 'RedisHighMemoryUsage'
    equal: ['instance']

  # 如果集群级别告警，抑制实例级别告警
  - source_match:
      alertname: 'RedisClusterDown'
    target_match_re:
      alertname: 'Redis.*'
    equal: ['cluster']

# 接收器配置
receivers:
  - name: 'default-receiver'
    email_configs:
      - to: 'admin@example.com'
        headers:
          Subject: 'Redis Alert: {{ .GroupLabels.alertname }}'
        html: '{{ template "email.default.html" . }}'

        title: '🚨 CRITICAL Alert'

  - name: 'warning-receiver'
    email_configs:
      - to: 'team@example.com'
        headers:
          Subject: '⚠️ WARNING: {{ .GroupLabels.alertname }}'
        html: '{{ template "email.warning.html" . }}'
    slack_configs:
      - api_url: 'https://hooks.slack.com/services/YOUR/WEBHOOK/URL'
        channel: '#alerts-warning'
        title: '⚠️ Warning Alert'
        text: '{{ range .Alerts }}{{ .Annotations.description }}{{ end }}'

  - name: 'platform-receiver'
    email_configs:
      - to: 'platform-team@example.com'
```

**静默管理脚本**：

```python
#!/usr/bin/env python3
# silence-manager.py

import requests
import json
from datetime import datetime, timedelta, timezone

class SilenceManager:
    def __init__(self, alertmanager_url):
        self.alertmanager_url = alertmanager_url

    def create_silence(self, matchers, duration_hours=1, comment=""):
        """创建静默规则"""
        starts_at = datetime.now(timezone.utc)
        ends_at = starts_at + timedelta(hours=duration_hours)

        silence = {
            "matchers": [
                {"name": name, "value": value, "isRegex": False}
                for name, value in matchers.items()
            ],
            "startsAt": starts_at.isoformat() + "Z",
            "endsAt": ends_at.isoformat() + "Z",
            "createdBy": "admin",
            "comment": comment
        }

        response = requests.post(
            f"{self.alertmanager_url}/api/v2/silences",
            json=silence
        )

        return response.json()

    def list_silences(self):
        """列出所有静默规则"""
        response = requests.get(
            f"{self.alertmanager_url}/api/v2/silences"
        )
        return response.json()

    def delete_silence(self, silence_id):
        """删除静默规则"""
        response = requests.delete(
            f"{self.alertmanager_url}/api/v2/silence/{silence_id}"
        )
        return response.status_code == 200

# 使用示例
if __name__ == '__main__':
    import os
    # 演示模式：未配置真实 Alertmanager 地址时打印请求参数而不发起网络调用
    alertmanager_url = os.environ.get('ALERTMANAGER_URL', '')
    if not alertmanager_url:
        print("演示模式：设置 ALERTMANAGER_URL 环境变量后连接真实服务")
        print("示例调用: create_silence(matchers={'alertname': 'RedisHighMemoryUsage'}, "
              "duration_hours=2, comment='Maintenance window')")
        import sys; sys.exit(0)

    manager = SilenceManager(alertmanager_url)

    # 创建静默规则
    silence = manager.create_silence(
        matchers={
            'alertname': 'RedisHighMemoryUsage',
            'instance': 'redis-01'
        },
        duration_hours=2,
        comment='Maintenance window'
    )

    print(f"Silence created: {silence['id']}")
```

## 9. 告警最佳实践

### 9.1 告警规则设计原则

**设计原则**：

1. **避免告警疲劳**：合理设置告警阈值和持续时间
2. **提供可操作信息**：告警描述包含处理建议
3. **分级告警**：根据严重程度设置不同响应时间
4. **避免重复告警**：使用告警抑制和分组

### 9.2 告警通知最佳实践

**通知最佳实践**：

1. **多渠道通知**：Critical告警使用多种通知方式
2. **告警聚合**：相关告警聚合发送，避免告警风暴
3. **告警静默**：维护窗口期间静默告警
4. **告警升级**：未处理告警自动升级

### 9.3 告警管理最佳实践

**管理最佳实践**：

1. **定期审查**：定期审查告警规则和通知配置
2. **告警演练**：定期进行告警演练
3. **持续优化**：根据实际情况优化告警规则
4. **文档化**：记录告警处理流程和Runbook
