## 1. 概述：多活的两难

缓存多活比 DB 多活更难：DB 有复制协议与共识工具，缓存的价值恰恰在于**绕过这些协议换性能**。两难：

- **真多活（双写）**：冲突仲裁、版本向量、合并语义——复杂度直逼 DB 多主，丧失缓存的简洁。
- **伪多活（主实例+温备）**：备机房缓存冷，切换瞬间命中率坍塌（回源风暴打到刚刚恢复的链路）。

**工程共识**（行业惯例，C 级）：缓存层接受"会话级多活 + 数据级温备"，强一致数据不放在缓存多活层（走 DB 多活的读接口）。

## 2. 形态一：会话级多活（sticky）

用户会话绑定单一机房（GSLB/网关按用户路由），缓存跟随会话——不存在跨机房缓存一致性问题。

| 要素 | 机制 | 故障行为 |
| ---- | ---- | -------- |
| 路由 | 网关按用户一致性哈希（cookie/uid）到机房 | 机房故障 → 该机房用户重新路由，会话缓存冷启动 |
| 会话缓存 | 机房内 Redis 集群，会话级 TTL | 切换机房 = 会话重新登录/重建（产品层接受） |
| 会话漂移 | 少量跨机房请求（移动端网络切换） | 按"无会话=重新认证"处理，不做跨机房同步 |

**适用**：用户态服务（社交、电商前台）。不适用：全局共享的计数/库存。

## 3. 形态二：数据级多活（双写+仲裁）

全局共享数据（商品库存、配置）需要双写时的设计：

```
写请求 → 本机房缓存 + 跨机房异步复制通道（MQ/binlog 风格）
         → 冲突仲裁：版本号 LWW（Last-Write-Wins）或 业务仲裁（库存走 DB）
```

| 方案 | 一致性窗口 | 实现 | 适用 |
| ---- | ---------- | ---- | ---- |
| 异步双写 + LWW | 秒级（通道延迟） | 应用双写 + 版本戳 | 展示类（商品详情），丢更新可接受 |
| 异步双写 + DB 仲裁 | 无（缓存不承载真相） | 缓存失效由 DB 变更广播（[04.04.08](../../04-架构设计/04.04-缓存问题与治理/04.04.08-缓存失效传播与一致性链路.md) CDC 链路跨机房） | 库存/资金 |
| 同步双写（双机房 WAIT） | 毫秒级 | 写路径串行两机房 | 延迟敏感业务不可接受（一次跨机房 RTT 30-60ms） |

**判据**：缓存 value 是否可重算（回源 DB 可得）→ 可重算选异步双写+版本，不可重算（缓存即数据源）则禁止多活双写（本质是用了缓存当 DB——设计错误，回 [03.02.06](../../03-Redis组件/03.02-持久化机制/03.02.06-持久化策略全局决策与成本模型.md)）。

## 4. 缓存温热与切换策略

备机房缓存"温备"三档（与 [04.04.09](../../04-架构设计/04.04-缓存问题与治理/04.04.09-缓存预热与冷启动治理.md) 的预热判据联动）：

| 档位 | 热度维持 | 切换时命中率 | 常态成本 |
| ---- | -------- | ------------ | -------- |
| 冷备 | 无 | ~0（全量回源） | 零 |
| 温备（推荐） | 影子读流量 5-10% 或 CDC 同步热点 | 60-80% | 备机房 10% 算力 + 链路费 |
| 热备 | 双机房全量双写 | ≥95% | 双份写成本 + 一致性复杂度 |

**温备实现**：本机房 CDC 消费端把热点变更推送到备机房（只推 Top N 热点，非全量——全量同步成本等同于双写）。

## 5. 切换的缓存一致性窗口

机房切换瞬间的缓存行为（时序分析，B 级）：

```
T0: 故障检测（GSLB 健康检查收敛，~30-60s）
T1: 流量切到备机房
T2: 备机房缓存服务（温备：命中率 ~70%；写路径：接受写但注意原机房可能复活）
T3: 脑裂窗口（原机房网络隔离但未死，若恢复上线需防双主写入——缓存无 epoch 仲裁，靠 min-replicas-to-write 与运维熔断）
```

**防脑裂三件套**：①备机房升主前确认原机房隔离（Sentinel/人工确认）；②原机房恢复后先作从库同步再开放写（[07.09.02 §3](../../07-运维与部署/07.09-弹性伸缩与自愈/07.09.02-自愈机制实践.md) 的 min-replicas 同样适用跨机房）；③TTL 兜底所有切换窗口的脏数据（宁可短暂旧值不可双写冲突）。

## 6. 场景

1. **同城双活**：会话级 sticky + 全局数据温备（CDC 推热点），切换 RTO <1min。
2. **异地灾备**：冷备 + 预案驱动预热（04.04.09 §2 大促预热时序改版为灾备恢复时序）。
3. **全球化应用**：多 Region 各自缓存 + 中心 DB 失效广播（CDC 跨 Region），与本节形态一同构。
