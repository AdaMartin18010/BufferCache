## 1. 升级路径与兼容性矩阵

| 路径 | 兼容性 | 依据 |
| ---- | ------ | ---- |
| 7.2 → 8.0+ | 向后兼容（RDB/AOF 格式升级可读写） | 官方升级文档（B 级） |
| 6.2 → 7.x | 需先升 7.2 再 8.x | 官方升级路径 |
| 8.x 线内补丁 | 滚动重启即可 | 语义化版本（补丁无协议变更） |
| Redis → Valkey 7.2 | 协议/数据格式全兼容（Valkey 是 7.2.4 分叉） | [03.05](../../03-Redis组件/03.05-Redis生态与版本演进/README.md)（B 级事实） |
| Redis 8 → Valkey 9 | 需校验：Redis 8 的 vector set 等新增命令 Valkey 无对应（功能分叉点） | 03.05 功能分水岭表 |

**升级前检查清单**：

1. 当前版本与目标版本的弃用命令 diff（`INFO server` + 官方 release notes 的 breaking changes 节）。
2. 客户端兼容性（RESP2/RESP3、新命令依赖）。
3. 持久化文件健康（`redis-check-rdb`/`redis-check-aof`）。
4. 备份（[TC-CLUS-006](../../../Testing/cases/04-集群/TC-CLUS-006-备份恢复演练.md) 流程先走一遍）。

## 2. 滚动升级流程（Sentinel/Cluster）

原则：一次只动一个节点、从库先行、每步验证、保持法定人数。

```text
1. 升级从库A：新版本进程拉起 → 验证 replication（master_link_status:up + offset 追赶）
2. 依次升级其余从库（每次间隔观察业务指标）
3. 主库切换：CLUSTER FAILOVER（Cluster）或 SENTINEL failover（Sentinel 环境用 TC-CLUS-003 的 pause 法）
4. 升级旧主（现从）：同步骤 1
5. 全量校验：cluster check / sentinel master 确认、抽样 SET/GET、INFO server 版本齐一
```

**Cluster 特有点**：升级期间避免 reshard（版本混布时迁移协议一致但风险叠加）；`cluster-require-full-coverage yes` 下每次重启都会短暂拒收缺槽流量——低峰窗口操作。

## 3. 引擎迁移：Redis → Valkey

动机：License 合规（AGPL 不可接受时，[03.05 §3](../../03-Redis组件/03.05-Redis生态与版本演进/README.md)）+ 成本（云默认 Valkey 低 20%）。

| 迁移方式 | 流程 | 适用 |
| -------- | ---- | ---- |
| 主从替换 | Valkey 实例作 Redis 的从库 → 切换 | 在线、回滚易（推荐起点） |
| 集群双写 | 应用双写两引擎 → 对账（[04.44.11](../../04-架构设计/04.04-缓存问题与治理/04.04.11-缓存数据对账与校验.md)）→ 切读 | 长期共存过渡期 |
| 重建灌数 | 离线 RDB 导入（Valkey 直接加载 Redis RDB） | 可停窗口 |

**工具链**：redis-shake（阿里开源，异构/同构同步）；valkey-cli 原生兼容 redis-cli 全部运维命令（运维手册不用换）。

## 4. 回滚预案

| 阶段 | 回滚动作 | 前提 |
| ---- | -------- | ---- |
| 升级中（从库阶段） | 停止升级，旧版本从库直接重切 | 未动主库 |
| 主已切换后 | 新主降级为从，旧主升回（需新旧版本互为主从兼容——7↔8 兼容，8→7 需确认新特性命令未写入 AOF） | 切换后写入窗口短 |
| 引擎迁移后 | Valkey 导出 RDB → Redis 加载（单向）；双写期直接切回 Redis 读 | 双写过渡期 |

**回滚硬约束**：升级/迁移前必须确认持久化文件双向可读（8.x 的 AOF 目录格式 7.x 不认——Multi-Part AOF 是 7.0 引入，6.x 回滚需导出转换，[03.02.04](../../03-Redis组件/03.02-持久化机制/03.02.04-Multi-Part-AOF.md)）。

## 5. 演练清单（TC-CLUS-009）

用 redis-lab 半年轮换执行：

1. Sentinel 环境滚动升级（7.2→8.x 或 8.x 补丁级），全程计时（每节点 ≤2min）。
2. 主库切换与回切各一次（TC-CLUS-003 方法）。
3. 引擎迁移演练：redis-m 挂 Valkey 从库 → 切换 → 抽样对账。
4. 回滚演练：升级后新写入若干 key → 触发回滚 → 验证新写入不丢（或按预案声明的可接受损失）。
