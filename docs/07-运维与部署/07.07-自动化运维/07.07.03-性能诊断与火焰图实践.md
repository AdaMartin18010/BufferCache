## 1. 诊断决策树

```text
延迟升高/吞吐下降
├─ 单实例指标：INFO 看 CPU/mem/rdb_bgsave_in_progress/evicted_keys
├─ 慢命令？→ SLOWLOG get 10（阈值 slowlog-log-slower-than 默认 10ms）
├─ 延迟事件？→ LATENCY DOCTOR（事件分类：fork/aoF-rewrite/expire-cycle/fast-command）
├─ 大 key 阻塞？→ memory usage/keyspace 采样（§4）
└─ 系统级？→ perf top 看 Redis 进程热点函数（§3）
```

## 2. Redis 内置诊断

| 工具 | 命令 | 产出 | 判读 |
| ---- | ---- | ---- | ---- |
| SLOWLOG | `SLOWLOG GET 10` | 最慢命令列表（命令+耗时+时间戳） | 看命令类型与 key 分布（是否同 key=热点；是否 O(N) 命令=bigkey） |
| LATENCY DOCTOR | `LATENCY DOCTOR` | 延迟事件诊断报告 | 事件名直接归因：fork（RDB/AOF 重写）、expire-cycle（过期风暴）、fast-command（命令突发） |
| LATENCY HISTORY | `LATENCY HISTORY fork` | 单事件时间序列 | 频率与幅度趋势 |
| INFO commandstats | `INFO commandstats` | 每命令累计耗时/usec_per_call | 找出平均耗时异常命令（call 数高 × per-call 高 = 真凶） |

**诊断顺序经验**（项目流程，C 级）：commandstats 找嫌疑命令 → SLOWLOG 看具体实例 → LATENCY DOCTOR 归因事件类型。三者交叉，单一工具都有盲区。

## 3. 系统级采样与火焰图

Redis 是用户态单线程进程，perf 采样热点函数可定位"Redis 把时间花在哪"：

```bash
# 1. 对 Redis 进程采样 30s（事件循环热点）
perf record -p $(pgrep redis-server) -g -- sleep 30
perf report --stdio | head -30          # 文本热点排序
# 2. 火焰图（需 FlameGraph 脚本）
perf script | stackcollapse-perf.pl | flamegraph.pl > redis.svg
```

**火焰图读法**（Brendan Gregg 方法，B 级）：看**平顶宽度**——decodeObject/deepGetIndexedKeyFromExpandableList（7.x 函数名）宽 = 大 key 访问；rdbSaveObject 宽 = fork 子进程序列化（正常）；lookupKey 宽 = 哈希冲突或热 key。

**Windows 演练替代**：Docker Desktop 容器内 perf 不可用 → 用 redis-lab 的**观测替代方案**：`INFO commandstats` 差分（压测前后对比）+ SLOWLOG 注入演练（§5）。

## 4. 大 key 定位三板斧

| 方法 | 命令 | 成本 | 精度 |
| ---- | ---- | ---- | ---- |
| --bigkeys | `redis-cli --bigkeys` | 全 keyspace 扫描（生产低峰） | top 1 per type |
| 内存采样 | `MEMORY USAGE key`（抽样脚本） | 抽 N 个 key | 估计分布 |
| RDB 离线分析 | `redis-cli --rdb dump.rdb` + rdb-tools（Python 解析） | 导出一趟 | 全量精确 |

**rdb-tools 分析内存分布**（实战命令）：

```bash
rdb -c memory dump.rdb --largest 100 > memory.csv   # top100 大 key
# 按 type/前缀聚合：找"某前缀 hash 平均 100 万字段"类结构性 bigkey
```

## 5. 诊断演练（redis-lab）

```bash
# 场景 1：慢命令定位
docker exec redis-lab-sentinel-redis-m-1 redis-cli -a lab-password --no-auth-warning CONFIG SET slowlog-log-slower-than 1000
docker exec redis-lab-sentinel-redis-m-1 redis-cli -a lab-password --no-auth-warning DEBUG SLEEP 0.05   # 注入 50ms 慢事件
docker exec redis-lab-sentinel-redis-m-1 redis-cli -a lab-password --no-auth-warning SLOWLOG GET 5
docker exec redis-lab-sentinel-redis-m-1 redis-cli -a lab-password --no-auth-warning LATENCY DOCTOR

# 场景 2：commandstats 差分（压测前后）
docker exec redis-lab-sentinel-redis-m-1 redis-cli -a lab-password --no-auth-warning INFO commandstats > before.txt
redis-benchmark -h 127.0.0.1 -p 6379 -a lab-password -n 5000 -t set,get -q
docker exec redis-lab-sentinel-redis-m-1 redis-cli -a lab-password --no-auth-warning INFO commandstats > after.txt
diff <(sort before.txt) <(sort after.txt)     # usec_per_call 变化 = 压测画像

# 场景 3：大 key 注入与定位
docker exec redis-lab-sentinel-redis-m-1 redis-cli -a lab-password --no-auth-warning EVAL \
  "for i=1,500000 do redis.call('LPUSH', KEYS[1], i) end" 1 drill:biglist
docker exec redis-lab-sentinel-redis-m-1 sh -c 'time redis-cli -a lab-password --no-auth-warning LRANGE drill:biglist 0 -1 | wc -l'
docker exec redis-lab-sentinel-redis-m-1 redis-cli -a lab-password --no-auth-warning --bigkeys
docker exec redis-lab-sentinel-redis-m-1 redis-cli -a lab-password --no-auth-warning UNLINK drill:biglist
```
